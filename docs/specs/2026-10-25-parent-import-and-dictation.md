# 家长端导入与词库交互重设计：教学进度、批量编辑与指定默写

日期：2026-10-25（北京时间）。用途：LuCeser/xiaotian 的规格事项；测试边界已由用户确认。

已发布：[规格 #80](https://github.com/LuCeser/xiaotian/issues/80)，分诊标签 `ready-for-agent`。

## Problem Statement

家长希望把词表交给小天，核对内容，再用日常语言说明孩子学到哪里或哪些词需要默写。目前完成这件事需要先理解“分组、待确认、课次顺序、加入范围”等概念，填写教材字段、维护课次名单，再处理练习资格。导入成功也不能保证有可默写内容，界面缺少直接可用的下一步。

2026-10-25 的只读核查发现，实际词库已有 39 个英语词条且参与开关均开启，但所属教材没有课次名单、进度为零，归属课次全部为空且未明确加入范围，因此自动选题结果为空。用户还反馈词条和归属信息挤在同一行，难以阅读，逐条编辑繁琐，缺少批量改词。

用户需要系统记住教材教学进度：“现在学到第三单元”意味着第一至第三单元都可以默写；也需要明确指定本次默写内容，而不被是否到复习时间限制。当前的保存、范围、选题与课堂结果没有通过清楚的交互形成完整用户流程。

## Solution

采用已选择的 A“并排核对”布局作为正式设计基础：在宽屏上，左侧显示本次材料及需要确认的学习安排，右侧显示可直接修改的词面与释义；教材和课次信息在适当的标题或次级区域表达，不挤占每个词条的主要阅读位置。窄屏按同样的任务顺序重排，不要求家长来回寻找隐藏操作。

照片识别尽量复用已识别的教材与课次信息，不要求家长先填写整套书目信息或逐行录入全书课次。小天结合已有教材、教学进度和本次识别内容，判断是否需要询问以及如何表述。第一次导入时可以问学到哪里；识别出超出已知进度的新内容时，询问是更新进度、只加入本批词，还是先保存；已知进度内的内容沿用进度，不重复提问。模型推测或上传动作本身不修改教学进度。

把三种不同含义落实到同一流程：记住教学进度、单独持续加入一批词、本次指定默写。保存回执明确区分保存数量和可安排默写的数量，并提供相应操作。指定默写使用全部符合资格的指定内容，结果同样更新后续自动复习安排。

## User Stories

1. **US-01** 作为家长，我希望上传词表照片后就能进入核对流程，以便不用先学习教材管理术语。
2. **US-02** 作为家长，我希望系统利用照片已经识别出的教材和课次信息，以便避免重复填写相同信息。
3. **US-03** 作为家长，我希望只确认当前需要的信息，以便不必先填写版本、学段、年级、册、模块等完整表单才能导入。
4. **US-04** 作为家长，我希望教材的课次和教学顺序由系统结合已有信息与材料整理，以便不必逐行手工维护完整课次名单。
5. **US-05** 作为家长，我希望无法可靠确定教材、课次或先后关系时只针对实际歧义确认，以便既能继续操作又不会把猜测当作事实。
6. **US-06** 作为家长，我希望在核对识别草稿时看到原图，以便方便地纠正识别错误。
7. **US-07** 作为家长，我希望宽屏下能同时看原图、词条和学习安排，以便减少在多个弹窗之间切换。
8. **US-08** 作为使用 iPad 的家长，我希望输入、选择和保存操作适合触屏，以便不用精确点击很小的按钮。
9. **US-09** 作为家长，我希望窄屏上仍能按顺序完成核对与确认，以便横竖屏变化不影响任务完成。
10. **US-10** 作为家长，我希望用“教材”和“课次”理解内容归属，以便不用判断额外的“分组”到底是什么。
11. **US-11** 作为家长，我希望词面和释义清晰易读，以便快速检查导入内容。
12. **US-12** 作为家长，我希望教材、课次与练习状态和词条主体分开表达，以便一行不会被大量标签挤满。
13. **US-13** 作为家长，我希望点击词面或释义即可修改，以便不用为每个词打开和关闭编辑弹窗。
14. **US-14** 作为家长，我希望连续修改多个词条后一起保存，以便高效处理一批识别错误。
15. **US-15** 作为家长，我希望勾选多个词条后批量编辑词面和释义，以便不必重复逐条操作。
16. **US-16** 作为家长，我希望可以粘贴从表格整理出的多条词面和释义，以便利用熟悉的工具完成批量纠错。
17. **US-17** 作为家长，我希望批量修改前看到受影响的词条和变更预览，以便确认修改没有对应错行或误覆盖。
18. **US-18** 作为家长，我希望能取消尚未保存的编辑，以便误操作不会被当作正式修改。
19. **US-19** 作为家长，我希望对一批词条统一指定教材和课次，以便不必重复设置归属。
20. **US-20** 作为家长，我希望编辑词面、释义或归属后保留词条身份和学习历史，以便纠错不会清空孩子的学习记录。
21. **US-21** 作为家长，我希望重新导入已有词条时继续合并来源并保留历史，以便同一内容不会变成多份互不相干的学习记录。
22. **US-22** 作为家长，我希望已有释义与照片释义不同时仍由我确认，以便批量操作不会静默覆盖内容。
23. **US-23** 作为家长，我希望批量保存按实际成功、待处理和失败结果反馈，以便知道还有哪些词需要处理。
24. **US-24** 作为家长，我希望说“现在学到第三单元了”就能更新并记住这本教材的教学进度，以便不用操作进度表单。
25. **US-25** 作为家长，我希望第三单元的进度包含第一、第二和第三单元，以便系统按累计教学进度安排默写。
26. **US-26** 作为家长，我希望记住教学进度本身不会立即开始默写，以便更新学校进度和发起本次任务可以分别表达。
27. **US-27** 作为家长，我希望不同教材分别记住教学进度，以便一本书的更新不会影响另一本书。
28. **US-28** 作为家长，我希望第一次导入一本教材时，小天能在流程中确认目前学到哪里，以便保存后有明确的学习安排。
29. **US-29** 作为家长，我希望导入已学范围内的内容时沿用已有进度，以便不用每次重复回答同一个问题。
30. **US-30** 作为家长，我希望导入第四单元而已知只学到第三单元时收到适当询问，以便选择更新进度或提前备课。
31. **US-31** 作为家长，我希望提前导入新内容不会自动推进教学进度，以便可以一次准备以后要用的材料。
32. **US-32** 作为家长，我希望明确同意学到第四单元后才改变教学进度，以便模型推测不会替我做决定。
33. **US-33** 作为家长，我希望可以只把本批词条加入默写而不更新教学进度，以便学校尚未学到该单元时也能安排这些词。
34. **US-34** 作为家长，我希望明确加入的词持续参与以后的自动安排，直到我明确移出，以便不用在每一轮重复加入。
35. **US-35** 作为家长，我希望系统决定已加入词条何时复习，以便不用手工管理每次复习日期。
36. **US-36** 作为家长，我希望可以只保存尚未准备学习的内容，并看到暂不自动安排的说明，以便提前导入不会造成意外选题。
37. **US-37** 作为家长，我希望说“这批词先加入默写”时系统理解是在改变范围，以便不会被误当作更新整本教材的教学进度。
38. **US-38** 作为家长，我希望识别或大模型服务不可用时仍能核对内容、明确选择学习安排或重试，以便不会被无响应的确认步骤困住。
39. **US-39** 作为家长，我希望明确说明的教材、课次和进度优先于模型判断，以便系统不会把我的纠正静默改回。
40. **US-40** 作为家长，我希望保存后分别看到已保存词数和可安排默写词数，以便不会把入库成功误认为所有内容都能被自动选中。
41. **US-41** 作为家长，我希望保存回执提供符合当前状态的下一步，例如加入范围或练习本次内容，以便不用去另一个页面寻找解锁方法。
42. **US-42** 作为家长，我希望已有词库也能通过更新进度、补充归属或明确加入范围恢复可练状态，以便不必删除并重新导入那 39 个词。
43. **US-43** 作为家长，我希望明确移出的词不会被重复导入或更新教材进度自动重新开启，以便已有排除决定继续有效。
44. **US-44** 作为家长，我希望说“今天默写第四单元”就能指定本次内容，以便不用先把这些词的复习时间改成今天。
45. **US-45** 作为参与默写的学生，我希望明确指定的单元有 20 个可练词时能练完这 20 个词，即使只有 5 个到期，以便课堂确实执行指定要求。
46. **US-46** 作为家长，我希望仅指定本次默写不会自动改变教学进度，以便临时任务和长期安排相互独立。
47. **US-47** 作为家长，我希望未指定内容时仍由系统自动安排复习，以便保留已有自动选题的价值。
48. **US-48** 作为家长，我希望同名课次在不同教材或学科中存在时系统确定正确对象，有歧义时再确认，以便不会混入另一教材的内容。
49. **US-49** 作为参与默写的学生，我希望指定默写和自动默写保持学科隔离，以便英语课堂不会混入语文词语。
50. **US-50** 作为家长，我希望明确指定的全部可练内容不会被旧的固定选词数量或缓存课堂悄悄截断，以便“整个单元”有一致含义。
51. **US-51** 作为参与默写的学生，我希望词量不足时按实际可练数量开始，并知道实际数量，以便课堂不会用别的内容凑数。
52. **US-52** 作为参与默写的学生，我希望没有可练内容时收到真实原因和可行的下一步，以便不会被笼统地要求重复添加已有词条。
53. **US-53** 作为家长，我希望指定默写的结果同样更新后续复习安排，以便系统利用这次表现安排以后学习。
54. **US-54** 作为参与默写的学生，我希望完成指定默写后能够正常检查、结束并查看结果，以便不会因为选词方式变化失去原有课堂流程。
55. **US-55** 作为家长，我希望批改结果、学习记录和复习安排的保存状态如实显示，以便部分保存失败不会被汇总为全部成功。
56. **US-56** 作为家长，我希望刷新后仍能读到已经保存的词条、教学进度和加入决定，以便功能真正影响后续课堂，而不只是改变当前页面显示。
57. **US-57** 作为家长，我希望这次改版继续支持已有英语和语文词语录入，以便常用能力不会在替换界面时丢失。

## Implementation Decisions

1. **采用 A 的信息结构，正式实现重新编写。** 原型确认的是并排核对方向，不能把原型中的所有按钮、示例文案或默认值视为逐项确认。保留现有家长端导航；宽屏并排、窄屏有序重排；核对区域支持连续编辑和批量操作。原型的模拟数据、固定回复、调试状态和方案切换器不进入正式产品。
2. **复用现有照片识别与词库能力。** 改造导入编排、词库展示和教材进度交互；已有单条和批量手动录入继续可用。不要重复搭建第二套词库或内容身份系统。
3. **教材信息按需要确认。** 识别草稿带出的元信息用于匹配已有教材或准备新教材；不把完整书目字段和全书课次名单作为普通导入的前置条件。课次顺序从可靠材料、已确认信息和家长说明中整理；保持教学顺序语义，不能靠课次名称的字典排序，更不能由模型臆造未提供的目录。补充或调整目录时，不得让已确认归属与教学进度静默改指其他课次。
4. **大模型理解表达和提出确认，正式数据由服务端核对。** 输入包括家长明确说明、识别教材与课次、已有教学进度和本批词条。输出须能区分更新进度、只加入本批、只保存、本次指定默写和需要补充信息；回复只引用可核实的教材、课次与数量。模型推测不能直接执行进度修改，失效或迟到的回复不能覆盖家长之后做出的选择。确认状态变化只作用于明确的教材和词条集合。
5. **确认融入核对流程。** 首次进度未知时确认教学进度；识别内容在已学范围内则沿用；超出范围时说明新旧课次，允许确认更新、单独加入或只保存。明确说“现在学到第 N 单元”按累计进度处理，不解释成仅本次选词，不自动开始课堂。若原始表达不足以消除歧义，只针对该歧义确认；服务不可用时允许通过简洁的可见操作完成同一决定。
6. **区分草稿选择与真实保存。** 保存前的编辑、归属和学习安排是待提交内容；成功回执以实际持久化结果为准。词条成功但归属、进度或范围更新失败时，分别反馈已经保存和未完成的部分，允许继续处理，不伪称所有词已可练。重试不能重复建词、丢失来源或覆盖后续明确选择。
7. **教学进度和明确加入相互独立。** 进度在教材内累计包含当前课次；导入本身不推进。明确加入可以作用于一批词条，持续有效且不修改教材进度。继续遵守现有练习资格合并规则、多来源任一满足即可，以及参与开关关闭优先排除的规则。重复导入不能清除明确加入，也不能重新开启已移出的词。
8. **稳定内容身份和学习历史保持既有规则。** 依照 ADR-0003，以精确词面与学科识别已有内容；重复导入合并来源，释义差异需明确确认。批量编辑按已有词条身份提交字段修改，不采用删除重建。词面改动导致身份冲突时展示相关词条并阻止静默覆盖或自动合并；保留既有学习记录、复习状态和历史课堂快照。释义来源、教材原文优先及缺失释义处理遵守既有 ADR，不借本次改版扩展生成能力。
9. **批量编辑提供预览和实际结果。** 至少支持词面、释义的批量修改以及教材课次的批量指定；明确当前选择影响哪些词条。粘贴内容与词条的对应关系必须可核对，异常、冲突和失败逐项呈现；取消未保存编辑不产生正式写入。是否采用单个批量端点或组合现有端点留给实施设计，但不得用循环弹出单词编辑窗代替批量交互。
10. **把指定选题接入真实课堂。** 显式区分自动安排和指定默写。指定目标依据学科、教材与课次的真实归属或明确词条集合解析，不能仅把教材课次名转发到旧的独立单元字段上。指定模式跳过“必须到复习时间”的限制，但仍遵守参与开关和已确认的练习资格；若目标内容尚未获得资格，解释原因并提供更新进度或明确加入的操作，而不是把未学内容默认为已学。
11. **整个单元不被旧限制悄悄缩减。** 指定单元且未限定数量时，完整覆盖该单元全部可练词；旧的默认 10／30 词、旧课堂快照或自动安排中的排除规则不能静默把它变成一小批。如果为资源限制分段执行，应明确告知并保证完整覆盖。活动课堂对同一内容的并发占用仍须正确处理，不能为指定模式取消并发保护。首次进入到结果保存的上下文应一致，不能在进入实时课堂后重新按默认到期词选题。
12. **指定模式复用正常结果写入。** 按本次实际核对的结果更新同一套学习记录和 FSRS 复习状态，不复用现有“加练只记录表现、不更新复习安排”的语义。没有实际结果的词不补造评分；重复提交不得多次推进复习状态。批改、课堂记录与复习写入各自如实反馈，失败不抹去已经完成的批改结果。
13. **空结果说明实际原因。** 至少区分无词条、归属／教学进度尚不满足、已明确移出、自动安排暂无到期词以及活动课堂占用或选词服务失败。不能把所有情况都翻译成“请先添加词汇”，不能用另一学科补足。自动安排暂无到期词时允许转为用户明确指定的练习；占用、失败和未到期不能混为同一种状态。
14. **保留既有数据，按需演进接口。** 沿用 Go 业务服务、Python 词库／复习写入和 SQLite 存储分工。新增接口或字段只为以上行为提供必要支持，不预先规定数据库重构；任何调整须兼容已有词条、归属、明确加入／移出决定、教学进度与学习历史。部署库中的 39 词问题应通过正常产品操作恢复，不把直接改库作为产品方案。
15. **协调已有事项而不改写历史。** 本规格是 2026-10-25 用户新确认的交互与指定默写增量，原最小版本事项的既有完成证据和排期不倒写。照片自动识别学科与已有事项 #75 复用或关联，本规格不再创建相互竞争的实现；用户显式指定学科仍优先，课堂保持单科。原有教材累计进度和自动安排限制保留；新增指定模式及其复习写入效果在实施事项中明确列出。

## Testing Decisions

**测试边界已确认。** 用户接受以完整浏览器用户流程为主要验收入口：导入并核对词条 → 确认进度或单独加入 → 保存 → 进入真实课堂 → 提交实际结果 → 刷新回看词库、教学进度与复习安排。自动化仅替换外部识别、大模型和语音提供方；应用、业务服务、Python 与隔离测试数据库保持真实。真实 HTTPS 和 iPad 验收另行记录，不能用固定回复原型代替。

- 好的测试通过可见操作、正式返回值和持久化后的业务结果判断行为；不测试内部函数调用次数、CSS 类名或偶然的 DOM 结构。布局使用必要截图及触屏操作验证，避免与实现逐行对应的断言。
- 优先扩展现有家长管理／照片导入／教材范围浏览器测试和家庭端到端流程，复用它们的隔离应用、真实 Python／SQLite、照片夹具及外部 MiMo 替身。课堂部分复用已有实时课堂的协议和结果保存测试设施，把家长决定与实际课堂词列表贯通，不另建内存版业务链来证明数据正确。
- 同一组浏览器流程覆盖导入编排、词库编辑、教材进度、范围规则、课堂选词和结果写入；必要时通过公开 API 或已有业务查询入口核对保存结果。对批量身份冲突、词条身份不变、并发占用和重复结果写入等浏览器不易完整观察的约束，补充少量现有服务／Python 集成测试，不为每个模块建立一套重复验收。
- 大模型替身覆盖已知进度内、首次导入、识别到新课次、明确用户纠正、歧义和服务失败；替身只控制外部响应，不绕过真实保存与范围判定。真实材料验收另确认识别、理解与询问是否自然，不能把关键词模拟器视为 LLM-first 已交付。

必须贯通的验收场景：

| 编号 | 操作与前提 | 可观察结果 |
| --- | --- | --- |
| AC-01 | 首次导入真实词表，不预先填写全套教材字段或完整课次名单 | 能进入原图对照核对；仅对必要信息确认；未提交草稿不进入正式词库。 |
| AC-02 | 回答“现在学到第三单元”，保存后刷新，再自动安排 | 教材记住第三单元；第一至第三单元满足已学条件，第四单元不因该回答进入范围；更新进度本身不开始课堂。 |
| AC-03 | 已知第三单元，导入第二或第三单元 | 沿用进度，不重复问学到哪里；保存后的资格与该进度一致。 |
| AC-04 | 已知第三单元，导入第四单元但尚未回应提示 | 上传和识别均未把进度改为第四单元。 |
| AC-05 | 在 AC-04 选择“学到第四单元了”并成功保存 | 第四单元进度可刷新读回，第一至第四单元满足已学条件；其他教材不变。 |
| AC-06 | 在 AC-04 选择“只把这批词加入默写” | 进度仍为第三单元，本批词持续参与；同单元未加入的其他词不因此全部获得资格，刷新与后续课堂仍保持该决定。 |
| AC-07 | 在 AC-04 选择只保存 | 词条实际保存，进度不变；回执明确暂不自动安排，并提供加入范围等有效下一步。 |
| AC-08 | 预置与实际 39 词问题同形的数据，家长通过界面明确加入 | 不删除重建词条，能进入真实课堂；词条 ID 和已有历史保留，无需代理直接改数据库。 |
| AC-09 | 连续改词、取消，再批量粘贴修改并预览、保存、刷新 | 取消没有正式写入；保存的词面与释义对应正确；身份及学习历史保留。重复词面、无效行与失败项可定位。 |
| AC-10 | 批量指定课次、重复导入已有词、处理释义差异 | 真实归属正确；同词不被重建；来源合并、历史、释义确认和明确加入／移出保护符合既有约定。 |
| AC-11 | 同一教材第四单元有 20 个可练词，只有 5 个到期；明确说“今天默写第四单元” | 实际课堂覆盖这 20 个词，不只返回 5 个，不被默认 10／30 词或既有日课堂缓存截断；教学进度不因此变化。 |
| AC-12 | 同时存在两本同名课次教材与两种学科，明确指定其中一本；另测表达歧义 | 明确目标不被模型改回；实际词列表不串教材或学科，歧义通过最少确认消除。 |
| AC-13 | 指定默写完成核对并提交，再刷新查看；另测重复提交和复习保存失败 | 按真实结果更新学习记录和复习安排，重复提交不多次推进；保存失败单独显示，不伪报全部成功。 |
| AC-14 | 未指定内容，使用自动安排；当前所有可练词均未到期 | 保持自动复习语义，说明暂无到期词；随后明确指定单元可以开始符合资格的练习。 |
| AC-15 | 已移出词被重新导入或其教材进度推进；另测尚未获得资格的指定内容 | 已移出决定不被自动恢复；资格不足时解释并给家长侧可执行操作，不用另一学科凑数。 |
| AC-16 | 保存中部分写入失败、大模型不可用或迟到，家长修改选择后重试 | 显示真实成功与未完成项，旧回复不覆盖新选择；不会重复创建词条、静默推进进度或虚报可练数量。 |
| AC-17 | 实际 iPad、真实 HTTPS、真实英语与语文词表 | 完成拍照、核对、必要确认、批量修改、保存、开课和结果回看；记录识别／语音实际体验，界面不要求精确点击或横向寻找隐藏主操作。 |

## Out of Scope

- 后续尚未积累的其他界面问题、全站视觉改版、通用组件去重和无关性能重构。
- 新建完整教材资源平台、联网获取整本教材目录、凭模型记忆生成未知课次或自动推断孩子已经学过哪些内容。
- 为单元指定练习绕过明确移出、取消并发保护，或把所有导入内容默认视为已学。
- 重写 FSRS 算法、新评分体系、能力测评、复杂复习策略或词条多义／按来源存多份释义的存储模型。
- 新增缺失释义生成、按需例句、多页 PDF、整首古诗或整篇课文的背诵／背默功能；已有能力按原事项保留和安排，不借本次扩展。
- 重做实时语音基础设施、改造无关的推进／延迟问题；若现有缺陷阻塞本规格端到端验收，在已有对应事项关联证据和必要修复。
- 把本地模拟原型当作正式大模型、真实保存、真实课堂或真实设备验收结果，或把一次性原型代码直接推广到生产。
- 本次规格发布不部署、不修生产数据、不推送或合并主分支，也不自动创建实施子事项。
