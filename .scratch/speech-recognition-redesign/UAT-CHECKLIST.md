# UAT 检查清单 — 语音听写系统上线前人工验证

对应 ticket 08 中无法由代理执行的人工验收项。逐项打勾并记录日期/结果；发现缺陷走 issue 流程。

前置：服务器已启动（`go run ./cmd/service/` 或部署的 service.exe），iPad 与服务器同一网络。

## A. iPad Safari 真机全流程（ticket 08 条目 1、7）

设备：iPad（iOS 17+，Safari）。每步观察控制台（Mac 连接 Safari 调试器）无报错。

- [ ] A1 打开首页，连接指示器 30s 内变「已连接」
- [ ] A2 点开始听写 → 首词音频 ≤1.5s 开始播放（掐表）；iOS 静音键不影响播放（Web Audio 不受影响）
- [ ] A3 逐词模式：每个词播完后自动进入录音；对着麦克风说答案 → ✓/✗ 反馈卡片 + 语音鼓励
- [ ] A4 控制按钮：暂停/继续/重读/下一词 各可用；Home 键切走再回来 → 音频可恢复（tap-to-resume 覆盖层如出现，点击后恢复）
- [ ] A5 批量模式：勾选开关 → 整场听写（期间无自动起录音）→ 表单出现 → 手填 + 📷 拍照识别 → 提交 → 逐行 ✓/🟡/✗ + 报告 + 语音鼓励
- [ ] A6 报告屏幕滚动正常、字符高亮可读；返回/刷新后可再开新会话（旧报告隐藏）
- [ ] A7 锁屏 30s 回来：会话仍在（或超时后有明确提示，不得白屏/卡死）
- [ ] A8 连续 3 场会话无异常（内存/音频不错乱：第 2、3 场首词正常播放）

## B. 儿童语音命令（ticket 08 条目 2）

对象：6-12 岁儿童（至少 2 名，一低年级一高年级）。需要 MIMO_API_KEY。

- [ ] B1 「暂停」「继续」「再读一遍」「下一个」各 5 次，识别成功率记录：__/20
- [ ] B2 儿童音调/语速下的误触发：安静 10s、咳嗽、背景电视声 → 不误触发命令
- [ ] B3 识别失败时的降级：按钮仍可用（语音只是辅助）
- [ ] B4 6-8 岁对 push-to-talk 交互无障碍（按住说话的时长掌握）

## C. 真实笔迹 OCR（ticket 08 条目 3）

样本：≥3 名小学生真实听写作业照片（铅笔、田字格/四线格、大小不一）。

- [ ] C1 清晰笔迹：正确率记录 __%（≥90% 为达标）
- [ ] C2 连笔/潦草：低置信时落入「请核对或修改」路径（不误判为对）
- [ ] C3 光线差/阴影/倾斜照片：要么低置信提示、要么失败提示重拍——不允许高置信错读
- [ ] C4 英文与中文词表各测一轮

## D. 性能基准（ticket 08 条目 4）

服务器侧（VPS 上执行）：

- [ ] D1 空载 RSS < 60MB（`systemctl status` 或 ps）
- [ ] D2 单学生会话中 RSS < 150MB 持续 10 分钟无上涨趋势（内存泄漏护栏）
- [ ] D3 听写响应延迟：词播完→可作答状态 ≤1.5s（真机掐表 5 次取均值）
- [ ] D4 提交答案→批改结果到达 ≤1.5s
- [ ] D5 TTS 反馈语音在批改结果后 ≤3s 开始播放（含 Python 合成）
- [ ] D6 `/health` 全绿；`/metrics` 可抓取
