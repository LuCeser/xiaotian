# 家长端导入与词库交互原型（一次性）

问题：哪种操作顺序能让家长理解并顺利完成照片核对、教学进度确认、批量修改和开始默写？

## 运行

在仓库根目录执行：

```powershell
node scripts/parent-interaction.prototype.mjs
```

启动器有限时检查就绪后返回。Windows 沙箱内启动的后台进程可能随调用结束而退出；在普通终端运行该命令，或使用已授权的沙箱外启动。

打开 http://127.0.0.1:4178/parent.html?prototype=interaction&variant=A 。底部按钮或键盘左右方向键切换 A/B/C，输入框内的方向键保留编辑功能。切换方案保留当前内存状态，刷新或“重置场景”重新开始。

## 三个方案

- A 并排核对：原图与学习安排在左，词条核对表在右。
- B 对话引导：识别结果、编辑内容、进度确认依次出现在导入对话里。
- C 按教材整理：教材和单元目录在左，核对、编辑与学习安排在右。

沿用真实 parent.html 的页头、导航、parent.css 字体和蓝白色系。原型服务器移除生产脚本，只注入原型脚本；无 API 代理，拒绝 API 请求与写请求。生产页面没有原型入口，也不会加载切换器。

## 演示内容

顶部可选择首次导入、已学范围内导入、导入新单元、词库批量编辑四种场景。

39 个词面与释义取自只读词库样本；课次归属、教材展示名和复习到期状态是模拟数据，不代表真实教材内容。第四单元使用 8 个额外示例词，并故意留一个拼写错误供核对。照片选择只显示本机图片，不进行真实识别。自然语言输入由固定示例规则模拟，未连接大模型。所有操作只修改页面内存，不写数据库、不调用语音、不运行真实 FSRS。

已确认规则见根目录 CONTEXT.md：进度累计包含当前单元；导入不自动推进；可独立持续加入本批词；指定单元练全部可练词；本次结果更新后续复习安排。原型保留“先保存”选项，并明确显示不能自动安排的结果。

批量编辑：勾选词条（不勾选则编辑当前显示全部），点击“批量粘贴编辑”，修改 Tab 分隔的词面与释义，预览差异后应用；词库中还需点击“保存修改”。连续编辑支持取消；词条 ID 保留。教学进度可输入“现在学到第四单元了”；指定练习可输入“今天默写第三单元”。

## 当前结论

2026-10-25，用户反馈“看起来 A 比较合适”，选定 A 的并排核对布局作为后续规格基础；B、C 保留为比较材料。具体界面细节尚未逐项验收，原型不直接作为生产实现。按 prototype 技能要求，完整原型保存到独立临时分支，后续在规格和实施 Issue 中关联。
