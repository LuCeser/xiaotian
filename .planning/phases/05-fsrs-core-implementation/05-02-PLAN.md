<objective>
Deliver the FSRS orchestration service layer (pkg/fsrs) that the rest of the system reaches for due-word selection (FSRS-01/02/03) and feedback-driven parameter updates (FSRS-04). This is a pure Go orchestration layer: it composes parameters, merges config defaults, forwards calls to the Phase 3 pybridge.Executor, and wraps errors with structured logging. It does NOT reimplement the FSRS algorithm (Python vocab_manager.py is the permanent engine per D-09/ADR). Then wire it into cmd/service/main.go, replacing the existing _ = pyBridge placeholder.

Purpose: Complete all four FSRS requirements by lifting pybridge.Executor's low-level subprocess contract into a business-semantic interface (SelectDueCards / UpdateRatings) with config-driven defaults and fetch-lock session isolation.

Output: pkg/fsrs/service.go + service_test.go (new package) and cmd/service/main.go (modified wiring).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller (Phase 7/10) → FSRSService | SelectOpts field values and ratings map keys/values cross into pybridge argv |
| FSRSService → pybridge.Executor → Python | argv slice (no shell) carries word/category strings to the subprocess |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-03 | Tampering | SelectOpts/ratings values reaching argv | medium | mitigate (inherited) | pybridge uses exec.CommandContext with an argv slice (no shell interpretation), mitigating shell injection at T-03-07; FSRSService adds no new subprocess path and must NOT construct argv directly (architecture rule — delegate to RunDue/RunReview) |
| T-05-04 | Tampering | unknown rating values in the ratings map | low | accept | ratings forwarded verbatim per executor.go contract; Python rating_map accepts only good/hard/again/easy and emits a Warning + skips unknown values (exit 0), so an invalid rating cannot corrupt FSRS state — it is harmlessly dropped |
| T-05-05 | Denial of Service | concurrent SelectDueCards/UpdateRatings calls | low | mitigate (inherited) | D-04: no FSRS-specific concurrency primitive; all calls share the Phase 3 global bounded semaphore (MaxConcurrent=2) inside pybridge.Bridge, preventing fork-bomb on the 1C/1G VPS |
| T-05-06 | Information Disclosure | error/log fields leaking secrets | low | mitigate | D-05: errors are wrapped with operational context only ("fsrs service: select due cards"); FSRSConfig has no secrets (D-24, guarded by Plan 05-01 reflect test); structured log fields carry component/rating_count/card metadata, never credentials |

No new package installs this phase (T-05-SC npm/pip/cargo: not applicable). All security controls are inherited from Phase 3 (pybridge) and Phase 1 (config/logging); FSRSService introduces no new external input path.
