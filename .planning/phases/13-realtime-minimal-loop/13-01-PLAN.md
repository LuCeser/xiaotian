executor.go 实现（先写测试见红再实现）：

1. `type AdvanceResult struct { NewIndex int; NewVersion int; Idempotent bool }`；`type ConflictError struct { CurrentVersion int }` 实现 Error() 返回 "version conflict"；哨兵 `var ErrVersionConflict = errors.New("lesson: version conflict")`，ConflictError 用 Unwrap 返回哨兵（errors.Is 可命中）。`ErrLessonNotFound`、`ErrInvalidLesson` 复用/定义于本包。
2. `type Executor struct`（内嵌 store 与 logger）+ `NewExecutor(store *Store, logger infra.Logger) (*Executor, error)`，nil-guard 同 Task 1 范式。
3. `GetLessonState(ctx, lessonID string) (Lesson, error)` — 直接走 store.GetLesson（读工具无幂等需求，R0 不记 tool_requests）。
4. `AdvanceWord(ctx context.Context, lessonID string, expectedVersion int, requestID string) (AdvanceResult, error)`，单事务（db.BeginTx + defer Rollback）按 RESEARCH Pattern 5 顺序：
   a. `INSERT INTO tool_requests(request_id, lesson_id, tool, result) VALUES(?, ?, 'advance_word', '')` — 唯一键冲突用类型化检测（Addresses review L-2）：`var serr *sqlite.Error`，`errors.As(err, &serr) && (serr.Code() == lib.SQLITE_CONSTRAINT_UNIQUE || serr.Code() == lib.SQLITE_CONSTRAINT)`（import `modernc.org/sqlite` 与 `modernc.org/sqlite/lib`；go.mod 已锁 v1.55.0），禁止对 err.Error() 做字符串包含匹配。命中即整体回滚，改走幂等命中路径：SELECT 该行 result 反序列化为 AdvanceResult、置 Idempotent=true 返回。result 为空串（首次写未完成即崩溃的残留）按 ErrInvalidLesson 处理，不当作成功。
   b. `UPDATE lessons SET current_index=current_index+1, version=version+1, updated_at=datetime('now') WHERE lesson_id=? AND version=?` — RowsAffected==0 时回滚并回读当前 version，返回 *ConflictError{CurrentVersion: 当前值}。
   c. `UPDATE tool_requests SET result=? WHERE request_id=?` 写入 AdvanceResult 的 JSON（保证幂等命中时返回的是首次真实结果）。
   d. Commit 后返回 {新 index, 新 version, Idempotent:false}。
   事务内 lesson 行不存在时（步骤 b 影响 0 行且回读也无行）返回 ErrLessonNotFound。
5. 每次写路径日志：`infra.F("component", "lesson/executor")` + lesson_id/request_id/expected_version/新 version 字段；冲突单独 Warn 一条。
6. AdvanceWord 事务上方固定注释（Addresses review L-3）：db.go 的 `SetMaxOpenConns(1)` 单连接池下，本事务持有唯一连接期间会短暂阻塞冻结栈 /ws 会话表写——R0 事务仅三条短语句可接受；任何加长事务的改动必须先重审此前提。
