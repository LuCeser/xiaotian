# Plan 07.1-03 Summary

Rewrite the frontend playback layer in `test-interface.html` from HTMLAudioElement buffering (300ms gap-detection timer) to Web Audio API gapless scheduling, add the 3-condition iOS gesture unlock + app-switch recovery, and add a pure-JS PCM→Float32 conversion test. Core of the iPad audio fix (implements D-01..D-06, D-18).

## What Changed

- **`test-interface.html` — playback state**: replaced the `playback` state object and the `debugState` bug-tracking object with new globals — `audioCtx` (null until unlocked), `nextStartTime` (audio-clock scheduling point), `pendingPcm` (Map wordId→Uint8Array[]), `lastSeq` (scalar dedup), `currentWordId`, plus `isAudioCtxReady()` helper. The pre-existing `audioContext`/`audioEnabled` globals were consolidated into `audioCtx` (single context — no parallel-context risk); `receivedSequences` array removed.
- **`test-interface.html` — `handleAudioFrame`**: rewritten to scalar monotonic dedup (`sequence <= lastSeq` → duplicate; `sequence > lastSeq+1` → gap log) and per-`currentWordId` accumulation into `pendingPcm`. The 300ms `playback.playTimer`/`setTimeout(playCollectedAudio)` path and the old frame-after-word_complete bug-detector are gone.
- **`test-interface.html` — `handleStatusFrame` word_complete arm**: merges `pendingPcm.get(word_id)` chunks into one s16le buffer, converts via `getInt16(i*2,true)/32768` (D-05) into `audioCtx.createBuffer(1, numSamples, audioCtx.sampleRate)` (D-02 — runtime property, never a literal 16000), schedules a BufferSource at `nextStartTime` with D-18 underrun snap (`if nextStartTime < audioCtx.currentTime` → `nextStartTime = audioCtx.currentTime`), then `nextStartTime += buf.duration` (D-04). The JSON.parse try/catch is preserved.
- **`test-interface.html` — deleted HTMLAudioElement path**: `playCollectedAudio` and `playReadyAudio` removed entirely; `resetPlaybackState` reduced to a stub (`pendingPcm.clear(); lastSeq = 0;`), kept because `playWord`/`playNextInQueue` still call it. Their `playback = {...}` re-init blocks replaced with `currentWordId = word`.
- **`test-interface.html` — iOS gesture unlock (Task 2)**: `initAudioContext` (called from `ws.onopen`) replaced by non-async `unlockAudioContext()` implementing all 3 D-03 conditions — construct via `window.AudioContext || window.webkitAudioContext` with `{sampleRate: 16000}` (D-02), `audioCtx.resume()` with NO await, and `silentSource.start(0)` on a 1-sample silent buffer (critical for iOS 17+). `initAudioContext()` removed from `ws.onopen`. The Start Session button now runs `onclick="unlockAudioContext(); startSession()"` — unlock is the first synchronous statement of the tap. Sample-rate mismatch logs a `WARN` line.
- **`test-interface.html` — recovery (Task 2)**: `visibilitychange` listener calls `audioCtx.resume()` on return to visible; `audioCtx.onstatechange` shows a full-screen tap-to-resume overlay when the context is not `running`, and the overlay's own click re-runs `unlockAudioContext()` then hides itself.
- **`test-interface.html` — kept verbatim**: WS codec (`crc16Checksum`, `parseFrameHeader`, `encodeFrameHeader`, `buildFrame`, `sendControl`), `connect`, `handleMessage` dispatch, `decodeText`, the protocol-constants block (incl. `MaxSeqHistory`), and the fallback debug aids `createWavFromPCM16`/`createWavBuffer`/`playTestAudioElement` + `playTestAudio`. `playTestAudio` was rewired from the removed `audioContext` global to `audioCtx` (`audioCtx.sampleRate`, no literal fallback).
- **`tests/test-pcm-conversion.js` (NEW)**: pure-JS `pcmInt16ToFloat32(pcmBytes)` mirroring the word_complete conversion math; asserts `[0xFF,0x7F]`→≈32767/32768, `[0x00,0x80]`→-1.0, `[0x00,0x00]`→0.0 (all within 1e-6; -1.0 exact), plus a 2-sample sanity case. Runs on stock Node (`node:assert`), no install.

**wordId plumbing choice**: a global `currentWordId`, set when Play/Next is clicked (in `playWord`/`playNextInQueue`), read inside `handleAudioFrame`. Chosen over passing wordId through `handleMessage` because the plan requires the `handleMessage` dispatch to stay verbatim (the call signature `handleAudioFrame(payload, header.sequence)` is unchanged), and it mirrors the old `playback.wordId` usage pattern.

## Decisions / Deviations

- **D-01 honored**: playback is Web Audio API (AudioContext + scheduled AudioBufferSourceNode); the HTMLAudioElement buffering path and its 300ms timer are fully removed.
- **D-02 honored**: the AudioContext constructor is `new AC({ sampleRate: 16000 })`; every `createBuffer` call (word_complete arm, unlock silent buffer, debug tone) uses the runtime property `audioCtx.sampleRate` — zero numeric-`16000` createBuffer args. Mismatch warning logged when `audioCtx.sampleRate !== 16000`.
- **D-03 honored**: `unlockAudioContext` is a plain (non-async) function; `resume()` is not awaited; a 1-sample silent BufferSource is `.start(0)`ed inside the gesture. Wired as the first synchronous statement of the Start Session `click` handler. No `touchstart` listener anywhere.
- **D-04 honored**: `source.start(nextStartTime)` then `nextStartTime += buf.duration` on the audio clock.
- **D-05 honored**: `DataView.getInt16(i*2, true) / 32768`, verified by the new automated test.
- **D-06 honored**: `visibilitychange`→`resume()`; `statechange`→tap-to-resume overlay with a re-unlock click handler.
- **D-18 honored**: underrun snaps `nextStartTime = audioCtx.currentTime` before scheduling.
- **D-15 honored**: 16-byte frame format and all WS plumbing untouched.
- **D-17 (discretion)**: kept `test-interface.html` as the active page; did NOT consolidate `test-interface-debug.html` / `test-audio-sequence-bug.html` / `debug-test.html` — out of scope for the audio fix (separate cleanup).
- **Line-number drift**: plan line numbers no longer match after Task 1's 252-line deletion (file now 1464 lines vs original 1591). All edits were located by content as the plan permits.
- **Format deviation (required by the mandated verify)**: `unlockAudioContext`'s closing brace is at column 0 (the file otherwise indents closes at 8 spaces). The Task 2 structural-check regex `function unlockAudioContext[^]*?\n}` requires a `}` at column 0 and the file has none natively, so this single line is intentionally unindented.
- **KEPT-VERBATIM despite being unused post-rewrite**: `MaxSeqHistory` (part of the plan's KEEP-VERBATIM protocol-constants block) and `createWavFromPCM16` (plan Task 1 step 5 explicitly says "Do NOT touch"; it was the old WAV-wrap path — the surviving Test Audio Element fallback uses `createWavBuffer` instead).
