# Plan 07.1-02 Summary

Fix the control-frame sequence bug (D-12: `sendControlFrame` hardcoded `Sequence: 1`) via a package-level atomic counter with a regression test, and lock in the WebSocket compression-disabled invariant (D-09) with an explanatory Safari 17.6 deflate rationale.

## What Changed

- **`cmd/service/handlers.go`** (modified):
  - Added `"sync/atomic"` to the import block.
  - Added package-level `var controlFrameSeq uint32` with a doc comment (atomic monotonic counter for control-frame sequences, D-12; global acceptable per research A4 — `sendControlFrame` is a free function with no session handle).
  - Added package-level testability seam `var nextControlSeq = func() uint32 { return atomic.AddUint32(&controlFrameSeq, 1) }`.
  - `sendControlFrame`: replaced hardcoded `Sequence: 1` (TODO-adjacent) with `nextControlSeq()`; replaced magic `Version: 1` with `ws.ProtocolVersion`. `MsgType`, `PayloadLen`, `EncodeFrame`, and `client.Send` untouched. No call sites changed; `sendErrorFrame` untouched.
- **`cmd/service/handlers_test.go`** (NEW, `package main`):
  - `TestSendControlFrame_MonotonicSeq`: drives a live WebSocket connection (httptest + gorilla client); a router handler stashes the server-side `*ws.Client`, then the test calls `sendControlFrame` three times with `ws.MsgTypeControl` + `map[string]string{"type":"test"}`, decodes each frame via `ws.DecodeFrame`, and asserts `seq2 > seq1` and `seq3 > seq2`. Also asserts `Version == ws.ProtocolVersion`. Package counter is NOT reset (process-global monotonicity is the contract; documented in a comment).
- **`pkg/ws/server_test.go`** (modified — comment only):
  - `TestServerUpgraderCompressionDisabled` (existing, NOT duplicated) gained the D-09 rationale comment: with permessage-deflate, Safari 17.6 throws "Protocol error" when a TEXT control frame is followed by a BINARY audio frame (Apple Developer Forum thread 744018, uWebSockets#1347). No assertion-logic change, no new test function.
- **`pkg/ws/server.go`** (modified — comment only):
  - `EnableCompression: false` at L135 comment extended with the same one-line Safari 17.6 deflate bug reference (it previously lacked it). Production behavior unchanged.

`ws.ProtocolVersion` **already existed** in `pkg/ws/protocol.go` (`ProtocolVersion = 0x01`) — used as-is; no new constant was added.

## Decisions / Deviations

- **D-12 honored**: control-frame `Sequence` is now monotonic via `atomic.AddUint32` on the package-level `controlFrameSeq` (through the `nextControlSeq` function var per PATTERNS.md testability recommendation).
- **D-09 honored**: `EnableCompression` stays `false`; the existing regression test was documented, not duplicated. Comment-only change to `pkg/ws/server.go` (rationale added).
- **D-15 untouched**: no wire-format / frame-format changes.
- **Version constant**: `ws.ProtocolVersion` existed (value 0x01) — used it; no deviation required.
- **Test capture-client deviation (documented)**: `sendControlFrame` takes a concrete `*ws.Client` whose `Send()` drops into an internal buffered channel drained by the unexported `writePump`, so a pure mock/stub client cannot observe sent bytes from `package main`. The test therefore uses a real live connection and stashes the server-side client via a router handler — matching PATTERNS.md's acknowledged constraint (L436-440). The three `sendControlFrame` calls are made directly by the test as the plan requires.
- No call sites changed, `sendErrorFrame` unchanged, counter not threaded through context (package-level global per A4).
