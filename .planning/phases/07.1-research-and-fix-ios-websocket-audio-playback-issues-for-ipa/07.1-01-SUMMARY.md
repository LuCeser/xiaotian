# Plan 07.1-01 Summary

Fix the two backend audio-sequence protocol bugs (D-10 startSeq off-by-one, D-11 per-word sequence reset) and wire the session-level sequence counter's cleanup into session teardown (Pitfall 5).

## What Changed

- `pkg/tts/streamer.go`
  - Added struct fields `seqCounters map[string]uint32` + `seqCountersMu sync.Mutex` after the prefetch/prefetchMu pair, mirroring its shape (doc comment cites D-11 + RESEARCH Pitfall 5).
  - `NewStreamer` now initializes `seqCounters: make(map[string]uint32)` next to the prefetch init.
  - Added `nextSeq(sessionID string) uint32` (lock seqCountersMu, increment map entry, return new value, defer unlock) — mirrors `PrefetchNext` locking discipline.
  - Added `ClearSeqCounter(sessionID string)` (lock, `delete(seqCounters, sessionID)`, defer unlock) — mirrors `ClearPrefetch`.
  - **D-10 fix**: removed the entire `if startSeq > 0 { startIndex = int(startSeq - 1) }` branch and its stale comments. New logic is purely 0-indexed: `startIndex := int(startSeq)`; clamps `< 0` to 0; if `startIndex >= len(frames)` calls `s.sendWordComplete(ctx, client, wordID)` and returns nil.
  - **D-11 fix**: `currentSeq := uint32(i + 1)` replaced with `currentSeq := s.nextSeq(sessionID)`. Frame-build block and send/error loop otherwise unchanged. 20ms ticker (D-16 deferred) and 16-byte frame format (D-15) untouched. `sendWordComplete` untouched.
- `pkg/tts/streamer_test.go`
  - `TestStreamWord_StartSeqPartial`: assertion changed from 3 → 2 frames (1 audio from frames[2] + 1 status) under 0-indexed D-10 semantics; first-frame sequence assertion changed from 2 → 1 (first `nextSeq` call for that session); explanatory comment rewritten.
  - `TestStreamWord_Basic`: misleading "Sequence should start from 1" comment reworded to "First call to nextSeq returns 1" (assertion value unchanged).
  - Added `TestStreamWord_SessionMonotonicSeq` (two StreamWord calls, same sessionID "session1", words "word1"/"word2" each 3 frames; asserts second call's first seq == first call's last seq + 1).
  - Added `TestStreamer_ClearSeqCounter` (modeled on `TestClearPrefetch`: StreamWord → ClearSeqCounter → StreamWord; asserts second run's first frame seq restarted at 1).
  - Added small helper `frameSeq(t, frame)` to decode the big-endian Sequence field.
- `pkg/session/session.go`
  - `SessionStreamer` interface gained `ClearSeqCounter(sessionID string)`, documented as the D-11 teardown hook bounding seqCounters memory under the 100-concurrent budget (Pitfall 5). `*tts.Streamer` satisfies it structurally after Task 1.
- `pkg/session/manager.go`
  - `onExit` closure in `NewSession` extended: after `m.removeSession(connID)`, it now calls `m.streamer.ClearSeqCounter(s.ID())` (the session ID keying StreamWord). Synchronous and non-blocking like `removeSession`. `removeSession` itself unchanged; no new Manager public API.
- `pkg/session/fakes_test.go`
  - `fakeStreamer` gained a no-op `ClearSeqCounter(sessionID string)` so it still satisfies the widened `SessionStreamer` interface.

- **D-15 (LOCKED) honored**: 16-byte frame header unchanged; `sendWordComplete` unchanged.
- **D-16 deferred**: 20ms ticker untouched.
