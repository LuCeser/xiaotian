## Summary

本阶段是把已有学习数据的「最后一公里」补上：数据早已落库（lessons 表有逐词判定/提示/阶段，practice_logs 有加练记录），但 Go 侧没有任何查询投影——`lesson.Store` 只有单课读取（EnsureLesson/GetLesson），`api.Handler` 构造器里根本没有 lesson 依赖。真正的缺口有三块：**①只读查询投影**（两张新 handler 路由＋两个新仓储方法，全部照现有模式扩）；**②诚实保存回执**（`submitted ≠ 已写入 FSRS`——四个提交终点都在 `finish*` goroutine 里，回执以「写前 pending 标记＋结果回填」两阶段挂进这四处）；**③家长/家庭界面**（parent.html 加页面级 tab、新建 home.html——静态根目录放文件即自动服务，零路由改动）。

本阶段**不需要任何新外部包**：SQLite 驱动（modernc.org/sqlite）、HTTP（net/http 标准库）、前端（原生 JS）全部现成。所有改造点都有清晰的最近先例：新表挂 `lesson.Migrate`、新路由照 `GET /words` 模式、新 JS 组件照 `BrowseView` 模式、mode 强制挂在 `normalizeSessionMode`＋TurnManagerConfig。

最需要 planner 注意的三件事：**进行中课次的泄题投影规则**（成功标准 2/7 的防线，有现成的 lessonViewStudent 投影先例可类比但规则更严格）、**「待核实」状态机的崩溃边界语义**（跨进程无原子事务是根因，Phase 15 才做对账）、**e2e mock server 没有 /api/v1**（家长页 mock e2e 需要补桩，或走真后端 e2e 先例 parent-management.spec.js）。

**Primary recommendation:** 按 consensus 执行顺序拆 4 个计划：回执表＋四挂载点 → 两个只读接口（Go 仓储＋handler）→ parent.html 学习记录 tab ＋ home.html ＋ tutor 回首页 → 家庭旅程真机验收（UAT）。

### Pattern 1: 保存回执两阶段写（本阶段核心新机制）

**What:** SubmitReview/RecordPractice 调用前先 INSERT 一条 status='pending' 的回执，结果回来后 UPDATE 为 saved/failed＋真实集合。进程崩溃→pending→家长端显示「待核实」；历史课 LEFT JOIN 无回执→「保存状态未知」。
**When to use:** 四个提交终点（check.go:600/812/892、practice.go:392）。
**为什么不能是单阶段写:** FSRS 写在 Python 子进程（cmd_review 一次 db.commit），回执在 Go 进程——跨进程无原子事务。崩溃窗口只有两种：FSRS 写完回执没落库（必须显示待核实，不能盲目重写——S-05 禁盲目重试），或两者都没发生（同样待核实）。两阶段写让两种崩溃呈现同一诚实状态。

```go
// 挂载点形态（以 finishCheckSubmit 为例，check.go:616-617 现有代码处）：
// [新] 1. 写前标记
rec, _ := receipts.Begin(ctx, ReceiptInput{
    LessonID: lessonID, RequestID: requestID, Kind: ReceiptKindCheck, Requested: keys(ratings),
})
// —— 现有代码 ——
wres, err := tm.cfg.Words.SubmitReview(ctx, ratings)
// [新] 2. 结果回填（err 与 wres.Updated/Missing 都是真实数据）
_ = receipts.Complete(ctx, rec.ID, receiptOutcomeFrom(wres, err))
```
**幂等键来源（全部已存在，勿新造）:** 正常/修正/加练＝客户端 `m.RequestID`（CheckSubmitMsg）；未核对兜底＝`lessonID+"-complete-check"`（check.go:907）；ClearUnchecked＝`lessonID+"-clear-unchecked"`（check.go:844）。

### Pattern 2: 只读接口投影（进行中课次防泄题）

**What:** `GET /api/v1/lessons` 列表对未完结课只返回 日期/词数/阶段；详情接口同理裁剪。完结判定：`stage == 'submitted'`（含 unchecked 兜底后的行——兜底也是 submitted，store.go:48/611），或 legacy 行 `stage==''` 且 `current_index >= len(cards)`（turn.go:547 的完结分支同款判定）。
**When to use:** 两个 lessons 路由的每一处序列化。
**先例:** `lessonViewStudent`（turn.go:675-685）是服务端投影 masking 的既有形态——但注意它比本阶段规则**宽松**（它在默写进行中就把已过词留空位、现行词之后的留空，而家长接口按 ROADMAP 是整课进行中一概不给词）。两套规则不要混用。

### Pattern 3: 新表挂 lesson.Migrate（幂等迁移先例）

**What:** `lesson.Migrate`（store.go:134-171）＝ `CREATE TABLE IF NOT EXISTS` 列表＋PRAGMA table_info 探测的 ALTER TABLE 回填。新回执表只需在 statements 切片加一条 DDL（照 practiceLogsDDL 形态），main.go:276 的启动调用自动生效。
**不要:** 自建迁移框架、版本号表——现有纯幂等模式覆盖需求。

### Pattern 4: 静态文件「放进去即服务」

**What:** `http.FileServer(http.Dir(staticDir))` 挂在 `/`（main.go:693），`/home.html` 放进 `pkg/web/static/` 即自动可达，且 `isHTMLDocument`（static.go:92-100）已给所有 `.html` 加 no-cache。parent.html 的 tab 改造与 tutor 页「回首页」都是纯文件改动。
**警告:** `/`（index.html＋index-banner.js）是 RT-10 降级备用——**一行都不能碰**；ServeMux 的 `/tutor/`、`/api/v1/` 长模式优先级已由现有注册保证。

### Pattern 5: mode 裁决单点

**What:** `normalizeSessionMode`（turn.go:568-573）是服务端唯一 mode 裁决点（session_init 时存 `tm.mode`，turn.go:484）。生产强制＝TurnManagerConfig 加布尔字段，normalize 时短路返回 student；配置链：infra.RTConfig（mapstructure）→ main.go rtTurnCfg（598-618）→ TurnManagerConfig。
**配置落地:** config.local.yaml（8443 家庭正式入口）设强制；config.yaml（本机 8080 开发）保持 `mode=test` 可用。默认值方向见 Open Questions。

### Anti-Patterns to Avoid

- **把「已提交」当成「已写入 FSRS」展示:** 家长页的保存状态必须来自回执表真实行，不能从 lessons.stage='submitted' 推导（stage 只说明检查流程走完，FSRS 写可能 pending/failed）。
- **用 review_logs 时间邻近猜配课次:** review_logs 只有 card_id/rating/reviewed_at（vocab_manager.py:161-167），无 lesson_id——consensus 评审已明确否决。
- **家长接口读 Python-owned 表:** cards/review_logs 的读也建议不碰（写分离红线 D-03-a，schema.go:6-11）；逐词详情所需的词面/判定/提示全部在 Go-owned lessons/practice_logs 里。
- **在课堂页面塞管理入口:** tutor 页只加终结态「回首页」，检查面板/控制区不动。
- **重试 FSRS 写:** S-05 禁盲目重试纪律（check.go:641 注释在案）——回执 failed/pending 都不触发自动重写，对账留 Phase 15。

| 保存状态展示逻辑 | 前端从多个表拼状态 | API 直接输出聚合后的保存状态字段 | 诚实语义（saved/failed/pending/unknown）由服务端统一裁决，客户端只渲染 |
| e2e 静态服务 | 新写 http 测试服务器 | mock-rt-server.js 已 root 在 pkg/web/static（:142） | URL 形态与生产一致（/tutor/、/parent.html 都能加载） |

**Key insight:** 本阶段几乎没有「新机制」——幂等、迁移、投影、静态服务、错误 envelope、fetchJSON 全部有现成实现。风险集中在**语义诚实性**（回执状态机与文案）和**投影规则的边界**（什么算「进行中」），不在工程构造。

## Common Pitfalls

### Pitfall 1: 「待核实」与「失败」混为一谈
**What goes wrong:** 回执 failed（SubmitReview 返回 err 或 updated<requested）与 pending（进程崩溃没回填）若显示同一文案，家长无法判断是否需要等下次补写；更糟的是把 pending 自动标成 failed 会诱导「再提交一次」→ 双写 FSRS。
**Why it happens:** 两者都「不完整」，前端图省事合并状态。
**How to avoid:** 回执 status 至少四态：saved / failed / pending（待核实）/ 无回执（保存状态未知）；文案逐字对应 ROADMAP。`updated < requested && err == nil` 是**部分保存**（saved 但带真实 M/N），不是 failed——check.go:638-643 的既有纪律。
**Warning signs:** 家长页出现「请重试」按钮（本阶段不该有——对账留 Phase 15）。

### Pitfall 2: 泄题投影漏边界
**What goes wrong:** 「进行中」判定写成只看 `stage==''`，漏掉 `stage='checking'`（检查面板开着、词表已揭示但课未提交）——此时词表在该学生屏上可见但课未完结，家长接口若返回词表会绕过 ROADMAP 防线。
**How to avoid:** 白名单式判定：**只有**（stage='submitted'）或（stage='' 且 current_index≥len(cards)）返回词数据，其余一律概要。用 turn.go:532-553 的分支表做穷举测试用例。
**Warning signs:** e2e 里没有「checking 阶段请求 /api/v1/lessons/{id}」用例。

### Pitfall 3: api.NewHandler 签名变更波及
**What goes wrong:** NewHandler 加参数后，main.go:679 唯一生产调用点要同步；cmd/service 与 pkg/web/api 的既有测试（handlers_test.go 901 行）全部要改构造调用。
**How to avoid:** 一次性改全（构造器 DI 纪律 D-42）；或收拢为 options struct。`go vet`/编译在第一个任务内完成。
**Warning signs:** 任何测试用 nil 依赖「凑合过」——lesson 查询路径 nil 依赖会 panic。

### Pitfall 4: SQLite 单连接下的读放大
**What goes wrong:** Go 侧全部 DB 操作共享**一条**连接（db.go:71-73）；若列表接口一次解析全部历史行的大 JSON 列（words/cards/verdicts/outcomes），课堂进行中的写（advance_word/CompleteCheck）会被排队卡顿，孩子端可感知。
**How to avoid:** LIMIT 硬上限＋只 SELECT 需要的列（practiceLogsColumns 先例：never SELECT *）；详情接口一次只取一行。rows.Close 用 defer（全仓一致）。
**Warning signs:** 上限参数没设服务端 cap（客户端 limit=10000 也能穿透）。

### Pitfall 5: e2e mock server 没有 /api/v1
**What goes wrong:** tests/e2e-rt/mock-rt-server.js 只实现 /rt WS＋静态文件；家长页 tab 的 mock e2e 直接 404。
**How to avoid:** 二选一：①在 mock server 补 `GET /api/v1/lessons*` 桩（node http handler，数据固定）；②走真后端 e2e 先例（tests/e2e/parent-management.spec.js，webServer=run.ps1 真服务）。推荐②为主＋①可选——真后端顺带验证 SQL 投影。
**Warning signs:** 计划里出现「在 e2e-rt 里测家长页」却没提 mock 桩。

### Pitfall 6: 「回首页」提前出现
**What goes wrong:** session_ended 一到就显示按钮，但 terminalDrain 尚未释放音频（播放在 drain 结束才真正完成）——违反成功标准 5「总结播完、音频释放后」。
**How to avoid:** 按钮挂在自然三理由（lesson_complete/practice_complete/no_due_words）**且** beginTerminalDrain 完成后的时机；word-controls.spec.js 已有「socket readyState=3＋stream=null」断言形态可复制（`__rtTutor.capture._stream`）。
**Warning signs:** 与 beginTerminalDrain 并行显示；或 playback_ack_timeout 错误路径也显示（该路径 session_ended 照发但语义是降级——按 ROADMAP 字面「课真正结束」，planner 决定是否含此路径并写入验收口径）。

### Pitfall 7: iPad Safari 特有约束
**What goes wrong:** home.html/parent.html 在 iPad Safari 上：①返回缓存（bfcache）显示旧 DOM；②脚本 MIME 错误拒绝执行（Go 侧已由 static.go:34 修好，但 mock server 也要 MIME 对齐——已有先例 mock-rt-server.js:11）；③ `?v=` 缓存戳漏改导致旧 JS。
**How to avoid:** 新 JS 文件照 `?v=20261009a` 形态打戳；真机验收用例含「看完学习记录→返回→再进」路径；isHTMLDocument 已给 .html no-cache，无需额外头。
**Warning signs:** 开发机 Chrome 通过＝真机 Safari 通过的错觉（13.1 UAT 已三次证明真机才作数）。

### Pitfall 8: parent.html tab 改造破坏既有能力
**What goes wrong:** 加页面级 tab 时把现有三个 section 包进隐藏容器，AddCard/BrowseView/SettingsCard 的挂载时序或尺寸计算（display:none 下挂载）出问题；或 e2e parent-management.spec.js 的选择器（#addSection 可见性断言）失效。
**How to avoid:** tab 切换用 hidden 属性切换（settingsSection 已是 hidden-then-mount 先例，parent.html:63）；既有 spec 全量跑过；组件挂载时机不变（defer 顺序）。
**Warning signs:** parent-management.spec.js tracer 用例红。

### Known Threat Patterns for Go＋SQLite＋vanilla JS 只读家庭页

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| 未揭示词经家长接口泄露 | Information Disclosure | 服务端序列化层白名单投影（Pattern 2）＋表驱动测试穷举 stage 分支 |
| SQL 注入 | Tampering | database/sql 占位符（全仓现有纪律，无字符串拼接 SQL） |
| XSS（API 数据渲染进家长页） | Tampering | textContent-only DOM 纪律（parent-app.js:124 Pitfall 10 先例；新 LessonsView 延续，禁止 innerHTML 拼接） |
| 路径遍历（静态服务） | Elevation | http.Dir 根容器（static.go:50-52 既有）；lesson_id 不进文件路径 |
| 单连接池被读查询拖垮（DoS 自伤） | Denial of Service | LIMIT 硬上限＋单行详情（Pitfall 4） |
| 盲目重试造成 FSRS 双写 | Tampering（数据完整性） | S-05 纪律：回执不驱动自动重写；对账留 Phase 15 |

**注:** 无门禁是记录在案的用户信任模型决策（「防不方便≠防孩子」，consensus 决策 2），research 不再建议门禁；防手滑两条（决策 3）由投影规则与 mode 强制承载。
