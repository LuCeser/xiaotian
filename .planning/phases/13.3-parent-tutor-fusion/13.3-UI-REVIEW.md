## Top 3 Priority Fixes

1. **Save-chip and verdict badge contrast fails WCAG AA** — `save-chip-saved` (#059669 on #ecfdf5, parent.css:1066-1069) ≈ 3.6:1 and `save-chip-pending` (#d97706 on #fffbeb, parent.css:1076-1079) ≈ 3.3:1 at 14px semibold — below the 4.5:1 AA threshold for text under 18.66px. This is the phase's core payload (the honest four-state save status) and iPads are often used in bright rooms. Fix: darken the text tokens on tinted backgrounds (e.g. #047857 green-700, #b45309 amber-700) or define dedicated `--chip-*-text` tokens — one-line changes in parent.css.
2. **Two competing accent blues across the family journey** — home.css/parent.css use `--accent: #2563eb`; the tutor 「回首页」 button hardcodes `background: #2f6fed` (tutor.css:283). The student navigates tutor→home on one button color and back on a slightly different blue; the "reads as one product" intent stated in home.css:8 is broken at the exact seam this phase built. Fix: make #2563eb the single value (or add a comment in tutor.css reconciling the deliberate difference — currently none exists).
3. **`.parent-tab` min-height 44px below the project's touch convention** — parent.css:143 sets 44px while home doors and `.rt-btn-home` use 60px and the phase's own UAT claims ≥60px targets (context_notes; tutor.css:277 comment "ipad-layout touch target"). The tab bar is the primary navigation of the parent workspace and is the shortest target on the page. Fix: `min-height: 48px` minimum (60px for parity), padding stays.

## Detailed Findings

### Pillar 1: Copywriting (3/4)
**Pass (strong):** The 13.3-03 verbatim contract is honored exactly in `parent-lessons.js` — four-state copy table (lines 63-68: 已保存/保存未完成/待核实/保存状态未知), judgement count format 「已核对 X 对 / Y 错 / Z 未确认」 (lines 269-270, 459-460), kind badges (71-75), receipt kinds (78-83), practice note 「加练记录：不调整复习计划」 (line 452), empty state 「还没有学习记录，开始今天的听写吧」 (line 229), error banners with actionable 「点「重试」再试一次。」 (lines 201, 362). Zero percentage strings in the file (grep = 0). The 13.3-03 consensus line 「已添加。新词将按复习安排选入课堂，不一定是下一课。」 is in parent-modes.js:53,353,660-683. No generic Submit/OK/Cancel patterns; 取消/确认删除 are contextual modal copy.
**Finding (WARNING):** parent.html:25 `<title>单词库管理</title>` and header lines 35-36 (「单词库管理」/「添加、整理孩子的听写词库」) describe the pre-13.3 page. The page is now the family workspace with 学习记录 as the default tab — the browser-tab label and the first heading a parent sees contradict what the page now is. Fix: title 「听写小助手 — 家长」 or 「家庭学习记录」; header subtitle 「学习记录 · 词库 · 学习设置」.

### Pillar 2: Visuals (3/4)
**Pass:** Clear focal hierarchy on every surface: home.html is one centered card with one primary (filled) and one secondary (outlined) door; lessons list uses date(weight 600) + pill badge + counts hierarchy; detail view separates actions/meta/counts/word rows/receipts into visually distinct bands. Icon-free design means no missing aria-label risk. `role=tab/tabpanel` + `aria-selected` + `aria-controls` correct (parent.html:47-53, parent-app.js:54-73).
**Findings (WARNING):** (a) tab touch target 44px (see fix 3). (b) The tablist lacks arrow-key support and focus management on switch (WAI-ARIA tabs pattern expects Left/Right roving tabindex; here tabs are plain buttons so keyboard users tab through — functional but not the declared pattern). Minor for the iPad-primary audience.

### Pillar 3: Color (3/4)
**Pass:** Accent #2563eb used sparingly and meaningfully (active tab underline, skip-link, stage label 「检查中」, home primary door) — roughly 60/30/10 with neutrals dominant. Four-state chips get genuinely distinct hues (green/red/amber/neutral), not color-only signaling (text copy always present).
**Findings:** (a) AA contrast failures on chips/verdict badges (fix 1). (b) Hardcoded hex in parent.css:1068/1071/1077 chip backgrounds (#ecfdf5, #fef2f2, #fffbeb) and tutor.css:283 (#2f6fed) instead of tokens — tutor.css hardcoding is a pre-existing file convention, but the *value* divergence from `--accent` is new in this phase (fix 2).

### Pillar 4: Typography (3/4)
**Pass:** Ramp is disciplined: 12px (chip note, 未核对 flag), 14px (all secondary/meta/badge text), 16px (body/tabs/word faces), 20px (card titles), 28px (page title). Weights: 400/600 only (700 once, on the tutor button). All sizes are explicit px in component CSS (no Tailwind scale), consistent with the repo's no-build convention.
**Finding (MINOR):** Two one-off sizes outside the system: home.css:121 `font-size: 17px` (doors) and tutor.css:280 `font-size: 18px` (回首页). Each is a single-use CTA size; neither matches parent.css's 16/20 steps. Harmless but they will tempt future one-offs.

### Pillar 5: Spacing (4/4)
Consistent 4px-grid values throughout: 4 (tab gap), 6/8 (chip/row gaps), 10/12 (paddings), 16 (section rhythm), 24 (header/tab margin), 32 (home card padding). No arbitrary `[...]px` values, no magic numbers off-grid, vertical rhythm in the detail view (2/4/6/12/16px) is coherent. Zero findings.

### Pillar 6: Experience Design (4/4)
State coverage is the strongest pillar and rare for vanilla-JS code:
- Loading: skeleton shimmer rows for list and detail (parent-lessons.js:185-193, 343-351; parent.css:793-805).
- Errors: inline banner + 重试 on list failure, detail failure, and fetchJSON timeout/abort normalization (parent-lessons.js:196-211, 354-375; parent-app.js:104-142).
- Empty states: lessons list (还没有学习记录…), receipts (没有保存记录, line 576), in-progress detail progress note (lines 463-467).
- Race safety: fetchSeq stale-response guard for list↔detail switches (lines 152, 166-180, 325-339).
- Degradation: missing LessonsView is non-blocking (词库/设置 keep working, parent-app.js:274-276); tab wiring runs before dependency checks so tabs survive a degraded page (parent-app.js:44-73).
- Restraint: the save-status area is deliberately write-free — only 刷新/返回列表/重试, no re-submit/re-judge (prohibition honored, lines 47-49).
- Destructive flows: browse modals pair 确认删除/取消 with cancel-first focus (parent-browse.js:769, 961); add submit disables + spinner under retained label (parent-modes.js:24).
- bfcache/return-cache and touch behavior verified by real-device UAT (13.3-UAT 10/10 passed).
