The MsgTypeControl handler is a closure that:
1. Decodes the JSON payload from []byte into a struct with Type string and Params json.RawMessage fields. If json.Unmarshal fails, send an error frame: build ws.FrameHeader{Version: 1, MsgType: ws.MsgTypeError, Sequence: 1, PayloadLen: ...}, encode a JSON payload {"type":"error","message":"malformed control frame"}, call client.Send(ws.EncodeFrame(&header, errorPayload)), and return nil (do not terminate the connection).

2. Switch on Type:
   - "start_session": Parse Params into a struct with Limit int, Category string. Call fsrsSvc.SelectDueCards(ctx, fsrs.SelectOpts{Limit: params.Limit, Category: params.Category}). If this fails or returns empty, send an error frame. Otherwise, extract word strings from the returned []pybridge.DueCard (card.Word field). Call gen.GenerateForSession(ctx, sessionID, words) where sessionID is derived from the client connection (use a generated UUID or the word count — Phase 7 will provide real session IDs; for now use fmt.Sprintf("session-%d", time.Now().UnixMilli())). After generation, call streamer.PrefetchNext(sessionID, firstWordIDs) where firstWordIDs is the first cfg.TTS.PrefetchCount words. Send a control frame response: {"type":"session_ready","session_id":"...","words":[...]} with the word list so the client knows what to expect.

   - "play_word": Parse Params into a struct with WordID string and SessionID string. Launch streamer.StreamWord in a goroutine: go func() { if err := streamer.StreamWord(ctx, client, sessionID, wordID, 0); err != nil { logger.Warn(...) } }(). The streaming runs asynchronously so the handler returns immediately (the Router worker is freed; frames are sent over time via the client's send channel). Pass the per-connection context (ctx from the handler) so disconnecting the client cancels streaming.

   - "select_due_cards": This is the existing FSRS query path used by the test interface. Parse Params for Limit/Category/Units/FetchLockHours, call fsrsSvc.SelectDueCards, and send a control frame response: {"type":"select_due_cards_result","result":{"cards":[...]}} matching the test-interface.html expected schema at line 541.

   - default: Log a warning "unknown control type" and send an error frame.

The MsgTypeAudio handler remains a no-op closure (return nil) — inbound audio from the client microphone is Phase 7+ scope. Add a comment documenting this.

The client must echo it back in play_word requests. This is the minimal contract to make the vertical slice work end-to-end.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client WebSocket → control frame JSON | Untrusted client input parsed into commands |
| Handler → FSRS/Generator/Streamer | Trusted internal dispatch |
| Session ID → filesystem path | Client-supplied session ID forms cache directory path |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-10 | Tampering | Control frame JSON injection | medium | mitigate | Handler validates JSON schema; unknown types rejected with error frame; no eval/exec path on JSON content |
| T-06-11 | Tampering | session_id path traversal | high | mitigate | Session ID generated server-side on start_session (not client-supplied); if client echoes it back, validate it matches pattern ^session-[0-9]+$ before using in cache paths |
| T-06-12 | Spoofing | Unauthorized play_word from wrong client | medium | mitigate | Phase 7 session management will bind session to connection; for Phase 6, the handler uses the requesting client's Sender so audio only goes to the requesting connection |
| T-06-13 | Denial of Service | Concurrent play_word flooding | medium | mitigate | ws.Router has per-type worker concurrency (default 4) and drop-oldest backpressure (Phase 2 D-73); streamer runs in a goroutine so handler returns immediately |
| T-06-14 | Information Disclosure | Error messages to client | low | mitigate | Error frames contain generic messages ("generation failed"), not internal paths or stack traces; detailed errors logged server-side only |
| T-06-SC | Tampering | No new packages installed | low | accept | Zero external Go dependencies added in this plan |
</threat_model>

- Server → Client: `{"type":"error","message":"..."}` (MsgTypeError, on failures)
