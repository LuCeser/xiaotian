Create pkg/tts/generator.go with:

Generator struct (fields: exec pybridge.Executor, cache *SessionCache, convertFn func(string, ConvertOpts) (PCMData, error), logger infra.Logger, cfg infra.TTSConfig). The convertFn field holds the MP3-to-PCM conversion function (defaults to codec.MP3ToPCM but injectable for testing — same pattern as pybridge's dependency on exec.Cmd).

Constructor NewGenerator(exec pybridge.Executor, cache *SessionCache, logger infra.Logger, cfg infra.TTSConfig) (*Generator, error) — validates exec is non-nil (wraps ErrTTSGenerationFailed), cache is non-nil, substitutes NoOpLogger for nil logger. Stores cfg for MaxRetries and GenerationTimeout access.

Method GenerateForSession(ctx context.Context, sessionID string, words []string) (map[string]string, error):
1. If len(words) == 0, return empty map and nil immediately (no subprocess spawn — same guard as pregenArgs in pregenerate.go line 84).
2. Call exec.RunPregenerate with PregenOpts{Words: words, Language: "english"}. If this fails, log the error with component="tts.generator" and return an empty map wrapped in ErrTTSGenerationFailed (the entire batch generation failed — caller should surface this).
3. For each MP3 path in result.Paths (indexed by position), call retryConvert with up to cfg.MaxRetries attempts. retryConvert calls the convertFn with a per-attempt context timeout of cfg.GenerationTimeout. On success, calls cache.Store(sessionID, wordID, pcmData.Samples) where wordID is derived from the word at the same index (or the path basename without extension if index exceeds words length).
4. If retryConvert exhausts all retries for a word, log a warning with the word ID and error, and continue to the next word (D-05: skip word, do not abort session).
5. Return a map[string]string mapping each successfully generated wordID to its cache path (filepath.Join(cache.SessionDir(sessionID), wordID+".pcm")).

The generator does NOT implement concurrency within a session — pregenerate_dictation.py already batches all words in one subprocess call (Phase 3 D-01), and the MP3-to-PCM conversion loop is sequential (each conversion is fast, ~100ms per word via ffmpeg). If future profiling shows this is a bottleneck, parallelism can be added without changing the interface.

Add a compile-time check: var _ Generator = (*Generator)(nil) is not needed since Generator is a concrete struct, but document that it has no interface satisfaction requirement yet (the AudioStreamer interface is for the streaming side).

Extract retryConvert as a method on Generator: retryConvert(ctx context.Context, mp3Path string) (PCMData, error). It loops up to g.cfg.MaxRetries times, each iteration:
1. Create a per-attempt timeout context: attemptCtx, cancel := context.WithTimeout(ctx, g.cfg.GenerationTimeout).
2. Call g.convertFn(mp3Path, ConvertOpts{SampleRate: 16000, Channels: 1, BigEndian: true}).
3. On success, return the PCMData immediately.
4. On failure, classify the error:
   - If errors.Is(err, ErrFFmpegNotFound): return immediately without retry (infrastructure failure, retrying will not help — same rationale as pybridge not retrying ErrPythonEmpty).
   - If errors.Is(err, context.DeadlineExceeded): log a debug entry "tts generation attempt timed out" with attempt number, then continue to next retry.
   - Otherwise (ErrPCMConversionFailed or unknown): log a warn entry "tts generation attempt failed" with attempt number and error, then continue to next retry.
5. After all attempts exhausted, return the last error wrapped in ErrTTSGenerationFailed with context "word generation exhausted retries".

Add CleanupSession(ctx context.Context, sessionID string) error method to Generator — delegates to cache.Cleanup(sessionID). This gives the session lifecycle (Phase 7) a single entry point to clean up TTS resources for a session. Log the cleanup with component="tts.generator" and the session_id.

The retry counter starts at 1 (not 0) so log messages read naturally: "attempt 1/3", "attempt 2/3", "attempt 3/3". The GenerationTimeout default of 120s means a worst-case single-word wait is 120s * 3 = 360s, but in practice ffmpeg conversion takes <1s per word and the timeout is a safety net.
