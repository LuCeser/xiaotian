<objective>
Build the audio streaming delivery layer: read cached PCM files, slice them into 640-byte WS-compatible audio frames, and stream them to connected WebSocket clients at real-time pace. This plan implements the "deliver" half of the TTS vertical slice.

Purpose: This is the core of DICT-03 (word prompts via TTS audio streaming). The streamer converts cached PCM bytes into a sequence of MsgTypeAudio binary frames and pushes them through the existing ws.Client.Send channel. Frame pacing at 20ms intervals matches 16kHz playback rate, preventing both send-buffer overflow (bounded at 16 messages) and client-side audio underrun.

Output: pkg/tts/streamer.go with Streamer struct implementing AudioStreamer interface, StreamWord method with frame pacing and context cancellation, and PrefetchNext for D-04 audio prefetch.
</objective>

Create pkg/tts/streamer.go with:

Streamer struct (fields: cache *SessionCache, logger infra.Logger, cfg infra.TTSConfig, prefetch map[string][]byte, prefetchMu sync.RWMutex). The prefetch map caches PCM bytes keyed by wordID for D-04 prefetch support.

Constructor NewStreamer(cache *SessionCache, logger infra.Logger, cfg infra.TTSConfig) (*Streamer, error) — validates cache is non-nil (wraps error "tts streamer: cache must not be nil"), substitutes NoOpLogger for nil logger. Initializes the prefetch map as an empty non-nil map.

Compile-time interface check: var _ AudioStreamer = (*Streamer)(nil).

Method StreamWord(ctx context.Context, client Sender, sessionID string, wordID string, startSeq uint32) error:
1. Load PCM bytes: first check the prefetch map (prefetchMu.RLock). If found, use the cached bytes. If not found, call cache.Load(sessionID, wordID). If Load returns ErrWordNotCached, return it directly (the caller should handle "word not generated" gracefully). Any other Load error is wrapped with context "tts streamer: load pcm".
2. Slice PCM into frames: call SliceToFrames(pcm, ws.AudioFrameSize) (640 bytes per frame).
3. Create a time.Ticker with 20ms interval (matching 16kHz frame rate: 1 frame = 20ms of audio). Defer ticker.Stop().
4. Loop over frames starting from index max(0, startSeq-1) (if startSeq > 0, skip earlier frames — D-06 breakpoint resume). For each frame:
   a. Wait for either ticker.C (time to send next frame) or ctx.Done() (cancellation). If ctx.Done(), return ctx.Err().
   b. Build the WS frame: construct ws.FrameHeader{Version: ws.ProtocolVersion, MsgType: ws.MsgTypeAudio, Sequence: currentSeq, Timestamp: uint32(time.Now().UnixMicro()), PayloadLen: uint16(len(frame)), Reserved: 0}. Call ws.EncodeFrame(&header, frame) to produce the complete 16+640 byte binary message.
   c. Call client.Send(encodedFrame). If it returns ErrSendBufferFull, log a warn "tts streamer: send buffer full, dropping frame" with word_id and sequence fields (drop-oldest per Phase 1 D-73, same as Router). If it returns ErrClientClosing, return immediately (client disconnected).
   d. Increment currentSeq.
5. After all frames sent, return nil.

The 20ms ticker is the frame pacing mechanism. It prevents flooding the ws.Client.Send channel (bounded at 16 messages, ~10KB) with all frames at once. At 50 frames/second, a 3-second word sends 150 frames over 3 seconds, keeping the send buffer comfortably under its 16-message capacity. The first frame is sent immediately (no initial ticker wait) to minimize time-to-first-audio for the DICT-05 latency target.

Add to pkg/tts/streamer.go:

Method PrefetchNext(sessionID string, wordIDs []string) — for each wordID, call cache.Load(sessionID, wordID). On success, store the PCM bytes in the prefetch map under prefetchMu.Lock(). On failure (ErrWordNotCached or any other error), log a debug entry "tts streamer: prefetch skipped" with word_id and continue (prefetch is best-effort per D-04 — failure here just means StreamWord will do a disk read later). This method is called by the session orchestration layer (Plan 06-04) after generating audio for the session, pre-loading the first cfg.PrefetchCount words so the first play_word request has zero disk-read latency.

Method ClearPrefetch(wordIDs ...string) — removes the given word IDs from the prefetch map under prefetchMu.Lock(). Called when a session ends or when cached audio is invalidated.

End-of-word notification: after the last audio frame in StreamWord, send a ws.MsgTypeStatus frame with a JSON payload {"type":"word_complete","word_id":"<wordID>"} encoded via ws.EncodeFrame. Build the JSON via encoding/json.Marshal (not string concatenation) to avoid encoding issues with non-ASCII word IDs. Use the same FrameHeader pattern but with MsgType=ws.MsgTypeStatus and PayloadLen=len(jsonPayload). This lets the client UI (Phase 8) know when to transition from "listening" to "waiting for input" state. If the status frame send fails (ErrSendBufferFull), log and continue — it is informational, not critical.

Also add an end-of-stream notification: after word_complete, if this was the last word in the session (indicated by a parameter or a separate method), send {"type":"session_complete"} so the client knows all words have been dictated. For this plan, just implement word_complete; session_complete is Plan 06-04 orchestration concern.
