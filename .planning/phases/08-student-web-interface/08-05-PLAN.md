## Gap Context (G-08-2)

**From UAT.md Test 2 (Static File Serving):**
- Expected: Navigate to server URL, student interface loads with proper MIME types
- Actual: HTML page loads correctly (text/html; charset=utf-8), but JS/CSS files return 404
- Severity: major
- Status: failed

**From debug/static-file-404.md Root Cause:**
Service runs from temp Go build directory (C:\Users\fortu\AppData\Local\Temp\go-build2890987147\b001\exe\service.exe) instead of repo root. Relative config.yaml path fails to resolve, LoadConfig() silently falls back to DefaultConfig() with StaticDir: "" (empty), which disables static file serving. Service then serves test-interface.html instead of pkg/web/static/index.html.

**Key Evidence Chain:**
1. Process running from temp directory → config.yaml not found at relative path
2. LoadConfig() (config.go:714-729) silently skips missing config, falls back to DefaultConfig()
3. DefaultConfig() (config.go:619) has StaticDir: "" → static serving disabled
4. main.go (lines 394-396) mounts debug handler when StaticDir is empty
5. Debug handler serves test-interface.html, which doesn't have CSS/JS files → 404s

**Why Code Is Correct:**
The code logic is working as designed. LoadConfig() is intentionally lenient (allows cross-CWD boot). StaticDir defaults to empty (opt-in behavior) following Database.Path precedent. The problem is purely operational: service startup procedure doesn't ensure correct working directory.
