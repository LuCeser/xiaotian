## Gray Area 1 — Orchestration model: auto-advance vs client-driven

| Option | Description | Selected |
|--------|-------------|----------|
| A — Backend auto-advance | After session_ready backend streams word 0; after each WordComplete auto-advances (no client round-trip) until queue exhausted, then session_complete. | ✓ |
| B — Client-driven | Frontend issues play_word/next_word per word; backend FSM stays client-gated. | |

**User's choice:** A (via "全部采纳").
**Notes:** Mandated by Phase 7 D-13 (system-driven) + the existing passive frontend
(no play_word/next_word senders). Eliminates per-word round-trips, preserving 07.1
gapless audio-clock scheduling. Blast radius confined to Go session layer.

## Gray Area 2 — FSM change for auto-advance

| Option | Description | Selected |
|--------|-------------|----------|
| A — Add `DICTATING + WordComplete` transition | Extend transition(): last word → WAITING_PARENT; else wordIndex++ → LISTENING (re-fires spawnStreamWord). FSM stays pure. | ✓ |
| B — Inject synthetic internal AutoAdvance event | Keep table unchanged; add new event type posted after WordComplete. | |
| C — Bypass FSM for advancement | Re-call spawnStreamWord from the loop without a transition. | |

**User's choice:** A.
**Notes:** Preserves FSM purity; minimal (one case, two branches); fits the existing
pattern (transition() already mutates wordIndex for next_word). Orchestrator added
**D-03 (word-0 auto-start)** as a refinement: handleStartSession currently returns
after session_ready leaving the session in IDLE — planner must auto-start word 0
(reuse IDLE+play_word→LISTENING, but triggered internally, not by a client frame).

## Gray Area 3 — `currentWordId` propagation (frame-drop fix)

| Option | Description | Selected |
|--------|-------------|----------|
| A — Add `word_id` to `progress_update` | Backend includes current word's id; frontend _applyProgressUpdate sets state.currentWordId. Backwards-compatible. | ✓ |
| B — Derive from `words[]` array | Frontend computes currentWordId = words[currentWord].id. | |
| C — Dedicated `word_started` frame | New frame type before each word's audio. | |

**User's choice:** A.
**Notes:** Resolves audio-controller.js:157-159 frame-drop (frames arrive with
currentWordId=null because nothing ever sets it). word_id must be set BEFORE that
word's audio frames arrive, so progress_update is emitted at the word boundary
before streaming.
