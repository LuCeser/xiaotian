# Phase 13.1 Plan 06: 检查阶段语音改判口令（D-06②）Summary

检查阶段语音输入路落地：孩子可以口头逐词判对错（「第一个词对了」）并口述实际写法（「apple 写的是 aple」），老师接话教学（对错确认话术/近错「差一个字母很接近了」鼓励）。语音与屏幕点按、OCR 预填汇流同一条 `ApplyVerdict` 幂等写（RT-07，语音 request_id 服务端生成且 version 烘进键）；分类走单独构建的检查段提示词（全词表＋逐词判定态，Pitfall 8），白名单扩到 11 值而 `parseIntentJSON` 校验不变；模型产的 index/text 载荷一律消费端校验——越界/缺失回退澄清话术零写入（T-13.1-13）；判对错是服务端确定性逻辑（人的口令＋GradeWord），LLM 无裁量权。

## Accomplishments

- **dictation.go（分类契约）**：`intentCheckRight/intentCheckWrong/intentCheckSpelling` 进白名单（11 值，注释同步）；`intentPayload` 增 `Index int`/`Text string`（解析形状化，消费端校验——模型输出不可信）；`buildCheckClassifySystemPrompt(words, verdicts)`：persona＋儿童安全措辞逐字承接，全词表 1-based＋每词判定态（已判定对/错、待确认识别、还没有判定），3 检查 intent＋6 合法基础 intent（hint 不提供，按 chat），输出契约 `{"intent","reply","index","text"}`（index/text 仅检查 intent 需要，text 原样记录绝不改正）；`classifyOncePayload` 抽取让检查段拿到完整载荷而 classifyTurn 签名不变；`appendShortHistoryLocked` 小抽取消重（行为逐字节不变）。
- **check.go（语音改判分发）**：`classifyCheckTurn` 镜像 classifyTurn 的单呼＋一重试纪律＋EventIntentClassified 脱敏发射，二次失败坍缩 chat＋固定兜底话术；`checkDispatch`：三个检查 intent 走 `applyVoiceVerdict`，resume 独立接话（清暂停位＋「好，我们继续检查。」），其余 intent 携无目标标记走既有 dispatchTurn（repeat/slow 重读、pause/resume 管暂停位、meaning/chat 播 reply），空回复兜底防 FSM 停在 speaking；`applyVoiceVerdict`：载荷校验（index 1..len、spelling 必带 text）→ 不合法播澄清话术零写入 → `ApplyVerdict(requestID=lessonID-verdict-<idx>-v<version>-voice, manual=true)` → check_verdicts 广播 → spelling 附 ocr_result 行侧条目 → EventVerdictApplied（仅首次提交）→ 接话过 `runAnnouncement` ACK 门（Pitfall 9：检查段绝不绕门）；冲突对齐真值重试一次，失败走 failTurn 如实报错；`verdictAckText`（「好，第 N 个词对了/错了」）＋`spellingFeedbackText`（对/近错「差一个字母很接近了」/再看看三档，全鼓励零羞辱）＋`checkVoiceClarifyText`（「你说的是第几个词？再说一次好吗？」）。
- **turn.go（管线分流）**：processTurn 在 checking 时改走 `classifyCheckTurn`（原直接丢弃），且跳过 advance-target 捕获（检查段 currentIndex==len(words)，turnTarget 会 panic——原丢弃注释里的红线条目就此拆除）；打码红线不变（检查段 maskedWords 空，display=原文）。
- **mock e2e（tests/e2e-rt）**：`?mock_voice_verdict=1`——`__test_voice` 测试-only 控制帧（`__test_resume` 先例）携带剧本台词，stand-in classifier 映射到检查 intent 后跑与真服务逐字段一致的帧序列（check_verdicts 回显＋ocr_result＋接话播报）；GradeWord stand-in（归一化相等=对、编辑距离 1 且词长≥2=近错）；无效载荷镜像澄清回退；session 记 voiceLines/voiceVerdicts 供断言。rt-loop.spec.js 新增四用例：right-verdict（行翻转＋「第1个词对了」接话＋混入门禁一次提交）、spelling（错判＋「识别：aple（好像差一点点）」行侧显示＋近错接话＋ocr_text 落 verdict）、mixed（1 语音翻转＋2 点按翻转→一次提交 requested=updated=3，RT-07 收敛）、clarification（无 index→「你说的是第几个词」零写入＋课堂存活）。

## Deviations from Plan

**[Rule 1 - 正确性裁定] check_spelling 的 verdict correctness 取 GradeWord.Correct 而非固定 false**
- **Found during:** Task 1 实现裁断
- **Issue:** 计划 action 写「check_spelling → same with correct=false」；但孩子口述「apple 写的是 apple」（念出且写对）时，固定 false 会落一个事实错误的 verdict——与 objective 明示的判对错权威「人的口令＋OCR＋GradeWord」直接冲突
- **Fix:** correctness = GradeWord(word, Text).Correct（服务端确定性逻辑，模型仍无裁量权）；aple/近错/远错各档与计划行为完全一致，仅「口述=词」档翻正
