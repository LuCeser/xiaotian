<objective>
Implement runtime memory tracking and 150MB budget enforcement (RES-01, D-13, D-18, D-68, D-69, D-70). The MemoryMonitor polls runtime.MemStats on a configurable interval, evaluates usage against three alert thresholds (80%, 90%, 95%), and triggers load shedding when usage crosses the LoadShedAtPercent threshold so the service stays within its 150MB budget under load.

This plan also delivers three foundational infrastructure patterns: thread-safe component internals via sync.Mutex per D-11, context-based resource cleanup per D-12 (cancellation propagates from caller to monitor goroutine), and the circuit-breaker pattern per D-15 (LoadShedder with hysteresis opens on overload and closes on recovery — the same resilience pattern Plan 08's server reuses at the worker gate).

Purpose: Plan 06 (connection limiting) and Plan 08 (server) must consult the memory monitor to decide whether to accept new work. Without this contract, those plans would have to invent their own backpressure signals, violating D-17 (centralized state) and D-18 (proactive load shedding).

Output: `pkg/infra/memory.go` (MemoryMonitor, LoadShedder, MemSource seam for testing), `pkg/infra/memory_test.go` with the VALIDATION.md-mandated `TestServiceMemoryBudget` test name.
</objective>

    Constructor `func NewMemoryMonitor(cfg MemoryConfig, source MemSource, loadShedder LoadShedder, logger Logger) (*MemoryMonitor, error)`:
    - Validate cfg: limit > 0, thresholds non-empty and sorted ascending and every value in (0, 100], loadShedAt >= max(thresholds), interval > 0.
    - Sort a defensive copy of cfg.Thresholds so caller errors do not affect monitor logic.
    - Return error if loadShedder is nil (require explicit callback for clarity).
    - If logger is nil, substitute NoOpLogger.
    - If source is nil, return error (force explicit choice — runtime source or fake).

    Method `(m *MemoryMonitor) Start(ctx context.Context) error`:
    - Acquire m.mu; if m.stopped is false AND a goroutine is already running, return ErrAlreadyRunning (new sentinel). Set running flag. Release lock.
    - Spawn goroutine:
      ```
      ticker := time.NewTicker(m.interval)
      defer ticker.Stop()
      for {
          select {
          case <-ctx.Done():
              m.logger.Info("memory monitor stopped")
              return
          case <-ticker.C:
              m.tick(ctx)
          }
      }
      ```
    - Return nil.

    Method `(m *MemoryMonitor) tick(ctx context.Context)` (unexported):
    1. `used := m.source.SysBytes()`
    2. `pct := Percent(float64(used) / float64(m.limit) * 100)` — guard divide-by-zero (limit > 0 enforced at construction).
    3. For each threshold in m.thresholds, if pct >= threshold, call `m.logger.Warn("memory threshold exceeded", F("threshold", int(threshold)), F("used_bytes", used), F("limit_bytes", m.limit), F("percent", int(pct)), F("component", "infra.memory"))`.
    4. If pct >= m.loadShedAt: acquire m.mu, if !m.shedActive: set shedActive=true, release lock, call `m.loadShedder("memory_budget_exceeded")`. If already active, no-op.
    5. If pct < m.loadShedAt: acquire m.mu, if m.shedActive: set shedActive=false (hysteresis reset), log Info "load shed cleared".

    Method `(m *MemoryMonitor) Snapshot() (used, limit uint64, percent Percent)` — returns current state for Plan 08 health/metrics endpoint. Calls source.SysBytes() once.

    Add sentinel errors:
    - `var ErrAlreadyRunning = errors.New("memory monitor already running")`
    - `var ErrInvalidMemoryConfig = errors.New("invalid memory configuration")`

    Constructor validation wraps ErrInvalidMemoryConfig with descriptive messages via `errors.Wrap`.

    Use `github.com/pkg/errors` (already in go.mod from Plan 02).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Go runtime → MemoryMonitor | runtime.MemStats values cross into the monitor; trust assumed (runtime is in-process) |
| MemoryMonitor → LoadShedder callback | LoadShedder is provided by the server (Plan 08); it gates whether new work is accepted |
| Operator config → MemoryConfig | Operator-supplied thresholds cross into monitor logic; validation at constructor rejects invalid ranges |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-14 | Denial of Service | Memory exhaustion via goroutine spam or runaway allocations | high | mitigate | Monitor polls Sys vs Limit and triggers LoadShedder at 95%, halting new work before OOM. Hysteresis prevents flapping. |
| T-01-15 | Denial of Service | Monitor goroutine leak | high | mitigate | Start honors ctx cancellation; TestMemoryMonitorStopsOnContextCancel proves goroutine exits within 200ms. |
| T-01-16 | Tampering | Operator misconfigures thresholds out of order | medium | mitigate | NewMemoryMonitor sorts a defensive copy and validates ascending order + (0,100] range. |
| T-01-17 | Denial of Service | Flapping load shed thrashes system | medium | mitigate | shedActive hysteresis flag ensures loadShedder fires once per crossing; clears only when usage returns below threshold. |
</threat_model>
