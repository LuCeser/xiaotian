<objective>
Implement the fixed-size worker pool with explicit backpressure signaling (D-10, D-18, D-22, D-72, D-74), per-task panic recovery (D-49), component redundancy via peer workers (D-16), and graceful drain (D-21). The pool bounds the number of goroutines handling in-flight work and surfaces ErrWorkerPoolFull to callers when the bounded queue is full — letting Plan 08's server translate that into an HTTP 503 or backpressure message to the client (graceful rejection per D-74).

Purpose: Plan 08 needs a WorkerPool to process per-session work without spawning unbounded goroutines (Pitfall 1). The Submit contract (task vs. error) must be locked here so the server layer doesn't reshape it. Multiple independent workers provide component-level redundancy per D-16 so a single slow or panicking worker does not stall the pool.

Output: `pkg/infra/worker.go` (WorkerPool, Task, Submit, drain), `pkg/infra/worker_test.go` covering processing, backpressure, cancellation, panic recovery, and drain.
</objective>

    Define `WorkerPool` struct:
    - `tasks chan Task` (buffered, size = cfg.QueueSize)
    - `size int` (number of workers; cfg.PoolSize)
    - `logger Logger`
    - `wg sync.WaitGroup` (tracks in-flight workers)
    - `running atomic.Bool` (guards double-Start)
    - `inFlight atomic.Int32` (in-flight tasks for stats)
    - `totalProcessed atomic.Uint64`
    - `totalPanics atomic.Uint64`
    - `totalBackpressure atomic.Uint64`

    Constructor `func NewWorkerPool(cfg WorkerConfig, logger Logger) (*WorkerPool, error)`:
    - Validate cfg.PoolSize > 0 (production default 2*runtime.NumCPU per research Open Questions).
    - Validate cfg.QueueSize > 0 (production default 256).
    - Create buffered channel `make(chan Task, cfg.QueueSize)`.
    - If logger nil, substitute NoOpLogger.
    - Return &WorkerPool{...}, nil. Validation failure returns ErrInvalidWorkerConfig.

    Method `(p *WorkerPool) Start(ctx context.Context) error`:
    - If `!p.running.CompareAndSwap(false, true)`: return ErrPoolAlreadyRunning.
    - Spawn `p.size` worker goroutines; each adds to p.wg before starting and calls p.wg.Done() on exit:
      ```
      for i := 0; i < p.size; i++ {
          p.wg.Add(1)
          go p.worker(ctx, i)
      }
      ```
    - Return nil.

    Unexported method `(p *WorkerPool) worker(ctx context.Context, id int)`:
    ```
    defer p.wg.Done()
    defer func() {
        if r := recover(); r != nil {
            p.totalPanics.Add(1)
            p.logger.Error("worker recovered task panic",
                F("component","infra.worker"),
                F("worker_id", id),
                F("recovered_panic", true),
                F("error", fmt.Sprintf("%v", r)),
                F("stack", string(debug.Stack())))
        }
        // Note: on panic, the worker continues unless ctx is cancelled.
        // To continue, wrap the channel select in a loop with the recover inside.
    }()

    for {
        select {
        case <-ctx.Done():
            return
        case task, ok := <-p.tasks:
            if !ok {
                return  // channel closed during Shutdown
            }
            p.runTask(ctx, task, id)
        }
    }
    ```

    Important: place the recover() INSIDE the for-loop iteration (not outside) so a panic on one task does not kill the worker. Restructure as:
    ```
    for {
        select {
        case <-ctx.Done(): return
        case task, ok := <-p.tasks:
            if !ok { return }
            func() {
                defer func() {
                    if r := recover(); r != nil {
                        p.totalPanics.Add(1)
                        p.logger.Error("worker recovered task panic", ...)
                    }
                }()
                p.runTask(ctx, task, id)
            }()
        }
    }
    ```

    Unexported method `(p *WorkerPool) runTask(ctx context.Context, task Task, workerID int)`:
    1. `p.inFlight.Add(1)`
    2. Defer `p.inFlight.Add(-1)`
    3. Call `task(ctx)`. If it returns an error, log Warn "task returned error" with component=infra.worker, worker_id, error fields.
    4. `p.totalProcessed.Add(1)`.

    Method `(p *WorkerPool) Submit(task Task) error`:
    1. Select with default to avoid blocking on full queue (per D-72 backpressure signals):
       ```
       select {
       case p.tasks <- task:
           return nil
       default:
           p.totalBackpressure.Add(1)
           p.logger.Warn("worker pool backpressure (queue full)",
               F("component","infra.worker"),
               F("queue_size", cap(p.tasks)))
           return ErrWorkerPoolFull
       }
       ```

    Method `(p *WorkerPool) Shutdown(ctx context.Context) error` (graceful drain per D-21):
    1. Close p.tasks channel — this signals workers that no more work is coming.
    2. Wait for either p.wg.Wait() to return OR ctx.Done().
    3. If ctx.Done() first, return ErrShutdownTimeout.
    4. Set p.running.Store(false) (allows restart; or document "one-shot pool").
    5. Return nil on clean drain.

    Method `(p *WorkerPool) Stats() WorkerPoolStats`:
    - Returns struct with InFlight, QueueCapacity, QueueLen, TotalProcessed, TotalPanics, TotalBackpressure.

    Define `WorkerPoolStats` struct with those six fields.

    Sentinel errors:

    - `var ErrPoolAlreadyRunning = errors.New("worker pool already running")`
    - `var ErrInvalidWorkerConfig = errors.New("invalid worker pool configuration")`
    - `var ErrShutdownTimeout = errors.New("worker pool shutdown timed out")`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller → WorkerPool.Submit | Caller-supplied Task closures cross into worker goroutines; panic recovery is the gate |
| Worker goroutine → Task | Task executes with worker's privileges; per-task recover prevents worker death |
| Pool → Task channel | Buffered channel caps in-flight work; backpressure is the gate against memory growth |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-28 | Denial of Service | Unbounded goroutine creation | high | mitigate | Fixed PoolSize (D-10) bounds worker count; bounded queue caps in-flight tasks. |
| T-01-29 | Denial of Service | Worker goroutine leak | high | mitigate | Workers honor ctx cancellation; TestWorkerPoolStopsOnContextCancel proves exit within 100ms. |
| T-01-30 | Denial of Service | Task panic crashes worker | high | mitigate | Per-task recover() inside worker loop; TestWorkerPoolRecoversTaskPanic proves worker survives. |
| T-01-31 | Denial of Service | Slow task exhausts pool (Pitfall 3) | medium | mitigate | Tasks receive ctx for cancellation; backpressure ErrWorkerPoolFull surfaces overload. |
| T-01-32 | Denial of Service | Backpressure flood wedges pool | medium | accept | Caller is responsible for translating ErrWorkerPoolFull to client response; default queue=256 absorbs bursts. |
</threat_model>
