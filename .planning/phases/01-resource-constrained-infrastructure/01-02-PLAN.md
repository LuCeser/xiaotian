<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator → config file | Operator-supplied config.yaml crosses into process; validation is the gate |
| Environment → process | Env vars are operator-controlled; typed parsing defends injection |
| Process → Config struct | Unmarshalled data crosses into Go memory; Validate() is the chokepoint |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Tampering | Unvalidated config input | high | mitigate | Validate() rejects zero/negative limits, oversized memory, unsupported strategy strings, malformed log levels. All numeric fields range-checked. |
| T-01-05 | Information Disclosure | Secrets in config files | high | mitigate | No secret fields on Config struct (D-24). Doc comment forbids adding them. Secrets consumed via os.Getenv directly in the consuming package. .gitignore blocks .env from commits. |
| T-01-06 | Tampering | Viper env binding case-sensitivity bugs | medium | mitigate | Explicit BindEnv() calls for every leaf field — does not rely on AutomaticEnv() heuristic alone. |
| T-01-07 | Denial of Service | Operator sets extreme values (e.g. 1TB memory budget) | medium | mitigate | Validate() caps Memory.LimitBytes at 1GB; Session.MaxConcurrent at 1000; absolute sanity caps above operational defaults. |
| T-01-08 | Repudiation | Missing audit of effective config at startup | low | mitigate | Plan 03 logging will emit "configuration loaded" with sanitized values at Info level (secrets excluded by design). |
</threat_model>
