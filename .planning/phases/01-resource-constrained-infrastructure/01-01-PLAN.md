<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer machine → git | Code commits cross this boundary; pre-commit hooks defend formatting/lint |
| git → CI runner | Source crosses into untrusted runner; CI uses pinned action versions and read-only token |
| CI runner → Go module proxy | `go mod download` pulls external code; go.sum pinning defends integrity |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-SC | Tampering | Go module installs (go.sum) | high | mitigate | Every Wave 2+ plan must `go mod tidy` and commit go.sum; CI fails if go.sum out of sync. golangci-lint gosec verifies no obviously malicious patterns at compile time. |
| T-01-01 | Tampering | CI workflow (third-party actions) | medium | mitigate | All actions pinned to major version (v4, v5, v6); `permissions: contents: read` limits blast radius; no `pull_request_target` trigger (avoids secret exfiltration). |
| T-01-02 | Elevation of Privilege | CI GITHUB_TOKEN | medium | mitigate | Token scoped to `contents: read` only; no deploy step in Phase 1; artifact upload does not require write perms to repo. |
| T-01-03 | Denial of Service | pre-commit hook timeouts | low | accept | Local developer concern; pre-commit hooks are opt-in via `pre-commit install`. |
</threat_model>
