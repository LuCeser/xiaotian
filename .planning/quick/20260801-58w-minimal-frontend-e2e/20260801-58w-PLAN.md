# Plan: 创建极简前端验证端到端技术栈连通性

## Task Description

创建一个极简前端，验证整个技术栈是否真正连通：
- 打开网页
- WebSocket自动连接
- 点击按钮发送测试消息
- 后端回复消息
- 页面显示回复

## Context

这个任务源于`/grill-with-docs`对话中发现的核心问题：项目已完成大量基础设施（WebSocket、Python桥接、配置系统），但完全缺少用户价值实现。各组件独立工作，但无法验证端到端流程是否通畅。

根据ADR-0001，项目的优先级框架是"快速反馈周期优先"，这个任务正是为了实现这一目标。

## Tasks

### Task 1: 添加静态文件服务到main.go

**文件**: `cmd/service/main.go`

**行动**:
1. 在publicMux中添加`/`路由，提供静态HTML文件服务
2. 创建`static/`目录用于存放前端文件
3. 使用`http.FileServer`提供静态文件服务

**完成标准**:
- 访问`http://localhost:8080/`能返回HTML页面
- 静态文件服务不会干扰现有的`/ws` WebSocket路由

### Task 2: 创建极简HTML页面

**文件**: `static/index.html`

**行动**:
1. 创建一个简单的HTML页面
2. 包含WebSocket连接逻辑
3. 包含连接状态显示
4. 包含一个测试按钮，点击发送消息
5. 包含消息收发显示区域

**完成标准**:
- 页面能正常加载
- 页面包含WebSocket客户端代码
- 页面有连接状态显示、测试按钮、消息显示区域

### Task 3: 修改handlers.go实现echo消息处理

**文件**: `cmd/service/handlers.go`

**行动**:
1. 将no-op handlers修改为简单的echo handler
2. 至少让一个消息类型能回复消息（比如MsgTypeControl）
3. 回复内容可以是简单的"Received: [原消息]"

**完成标准**:
- WebSocket收到消息时不再只是`return nil`
- 客户端能收到服务器的回复消息

## Verification

完成后，应该能够：
1. 启动服务：`go run cmd/service/main.go`
2. 打开浏览器访问：`http://localhost:8080/`
3. 看到页面显示"WebSocket: 已连接"
4. 点击测试按钮，发送消息
5. 页面显示服务器回复的消息

这样就验证了整个技术栈的连通性：浏览器 → WebSocket → Go后端 → WebSocket → 浏览器
