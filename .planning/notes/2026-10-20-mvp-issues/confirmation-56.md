父目标 #1；完整流程验收 #58。本项处理当前词播报结束、等待孩子完成时的确认语识别与推进，包含最后一词结束。相关语音长时间等待与 #41 对照。

状态：用户已补充明确发生时机与实际误判表现，产品行为清楚，保留 `ready-for-agent`。当前版本复现、具体原因和修复效果仍由 Agent 调查验证。

## 来源与现象

来源：2026-10-11 QA 记录（docs/qa-issues-2026-10-11.md）及 2026-10-20 用户补充。

原记录：默写中说“好了 / 下一个 / 好嘞”等确认语后，没有进入下一词，系统表现得像是在回应上一句话。

用户最新明确：**问题发生在当前词已播报完、等待孩子写完时**。“好了”“好嘞”这类肯定表达经常被解释为重读一遍或其他含义，没有被理解为“当前默写词汇已完成，应推进到下一个词”。

这次确认的是播报结束后的语义误判，不以此推断播报期间的打断行为。也不能仅凭用户描述就认定问题一定出在模型、转写或某个状态处理环节。

## 已确认的期望行为

- 在等待孩子完成当前默写词的上下文中，“好了”“好嘞”等表示已经完成的肯定语应识别为完成确认，推进到下一词。
- 同样支持明确的“下一个”推进指令；不能要求孩子必须使用这个固定说法才能继续。
- 单纯的完成确认不应触发当前词重读或无关对话；“重读”应有相应语义依据，例如明确要求“再读一遍”。
- 每次有效确认只推进一个词；最后一个词确认后进入正常完成状态。
- 确认语含义要结合当前任务状态理解，不能在其他对话状态中一律推进默写。

## 复现场景

1. 发起包含多个词的默写，等待当前词完整播报结束。
2. 在系统等待孩子完成当前词时，分别说“好了”“好嘞”“下一个”。
3. 检查系统实际执行的是推进、重读还是其他处理；核对下一词播报及当前索引。
4. 最后一词重复该确认场景，检查是否正常结束。

重点复现“好了 / 好嘞”被当成重读或其他意图的情况。原始记录未明确哪次测试中“下一个”单独成功或失败，需一并回归，不预先标为已正常。

## 验收条件

- [ ] 当前词播报结束且处于等待完成状态时，“好了”“好嘞”等明确表达完成的肯定语能推进到下一词，不触发当前词重读或其他意图。
- [ ] “下一个”同样能推进，不要求用户把自然肯定语改成固定命令。
- [ ] 每次有效确认只推进一个词，不重复当前词、跳词或仅生成口头回应。
- [ ] 明确要求“再读一遍”时仍能重读当前词，不被本次修复一并当作完成确认。
- [ ] 对“还没好”“等一下”等未完成或等待表达，不因部分字面相似而误推进。
- [ ] 最后一个词确认后正常完成，之后能按 #58 的流程重新发起任务。
- [ ] 非默写状态下不把肯定表达一律转换成推进动作。

## Agent 需补充的诊断证据

- 当前可复现的版本、入口和具体触发步骤。
- 同一次失败中，语音转写文本、任务状态、意图识别结果及实际执行动作；记录足以区分重读与推进的证据。
- 对比原始音频表达与转写，定位是转写偏差、上下文缺失、意图判断、状态处理还是动作执行的问题；尚未确认根因。
- 复用隔离测试验证推进和误判场景，并以真实语音验证“好了 / 好嘞”。自动化通过不能替代真实语音交互验收。
